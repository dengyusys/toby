# AI 模型设置：运行时可配置、服务端存储

[English](ai-runtime-settings.md) | 简体中文

AI 模型与各供应商的 API key 可在网页设置页（PC 与移动端）中于运行时
配置。持久化在服务端：一个 `settings` 域，拥有自己的按域数据库
（`data/settings.db`），API key 作为 pi-ai 凭证经 pi-ai 自身的
`CredentialStore` 端口入库。设置写入后在下一次 AI 请求即生效——
无需重启，无需重载。请求超时刻意不作为用户设置：它仍是运维事务，
经 `TOBY_AI_TIMEOUT_MS`（默认 30 秒）控制。

## 为什么

- **key 必须住在调用发生的地方。** 所有 AI 传输都跑在服务端进程
  （`infrastructure/model/`），凭证必须在调用时刻可被服务端解析。
  存浏览器会迫使 key 随每个请求往返——比存起来更糟。"前端可配置"
  指的是*界面*在前端，从来不是存储在前端。
- **pi-ai 已经定义了凭证端口。** 用 SQLite 实现它的 `CredentialStore`
  ——而不是发明一套设置格式——免费得到正确的语义：已存储的凭证独占
  该供应商，仅在无存储凭证时才回落到环境变量；`modify` 保持串行的
  读-改-写，恰好就是仓储规则（"一次校验过的事务性写入"）。
- **一张表是最便宜且正确的形状。** 非密钥设置一张 KV 表加一张
  凭证表，遵循按域数据库布局；基于文件的存储会破坏事务性写入规则。

## 存什么，谁优先

| 设置项         | DB 键      | 回退                               | 全部未设置时    |
| -------------- | ---------- | ---------------------------------- | --------------- |
| 模型           | `ai.model` | `TOBY_AI_MODEL`                    | AI 路径回答 501 |
| 供应商 API key | 凭证表行   | 供应商环境变量（如 `ZAI_API_KEY`） | 该供应商未配置  |

解析按请求进行。模型校验（`provider/model` 格式）在环境变量解析器与
设置 API 之间共享，两个来源不会漂移：一个通不过启动校验的环境变量
组合，同样通不过要存储它的 PUT。

## 安全姿态

- **key 以明文存于 `data/settings.db`。** `data/` 本就是安全边界——
  SQLite 数据库自身就在其中，`data/` 下的一切默认无人触碰的生产
  数据。静态加密会增加主密钥管理负担（丢密钥即丢全部已存凭证）却
  不移动边界；仅对凭证表加密保留为未来可选变更。
- **读接口永不返回 key。** 设置接口只回答掩码预览（`sk-…abc`）与
  来源（`stored` / `env`）。设置页的密码输入框不回显，保存成功后
  即清空。
- **路由默认在会话守卫之后。** 未启用认证时，其暴露面与该模式下
  的所有其他路由一致——设置不引入新姿态。
- key 永不进入源码、文档、日志、追踪或测试夹具。

## 运行时应用

单发客户端与 agent 工厂按请求解析有效配置与目录模型（同步查表，
开销可忽略），因此设置写入后的下一次调用即生效。"任何地方都没配
模型"继续经既有的 chat/ledger 映射回答 `unconfigured`（501）——
与仅环境变量时代完全一致的线上行为。`TOBY_AI_*` 仍是一等引导：
既有部署原样继续工作，设置界面只是覆盖它们。

## 测试

自动化测试永不触碰真实 key 或真实供应商：临时数据目录、假 key
字符串、faux 供应商。运行时切换测试证明：在数据库中更改模型会
改变下一次请求所用的模型。
