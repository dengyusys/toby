# 文档维护约定

[English](living-docs.md) | 简体中文

文档只维护两类内容:**行为契约**和**设计决策**。

- `features/`:记录各业务域的职责、行为约定、安全边界和验收标准。
- `decisions/`:记录架构与技术选型的原因,以及做出选择时考虑的取舍。
- `system-overview.md`:记录系统架构地图,在架构发生变化时更新。
- `README.md`:文档索引。

实现细节以代码为准,开发进度以 Git 提交历史为准,不在文档中重复维护。

## 维护规则

- 行为契约变化时更新对应的 `features/` 文档。
- 新的设计决策单独记录,不覆盖已有的决策历史。
- 被替代的决策标记为 `Superseded`。
- 方案讨论定稿后,将结论归入对应文档,删除临时讨论稿。

文档的目标是让人快速找到可信的信息,而不是完整记录开发过程。
