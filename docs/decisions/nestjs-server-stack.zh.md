# 为什么用 NestJS

[English](nestjs-server-stack.md) | 简体中文

不引入框架,路由、依赖注入、模块装配、请求管道(校验、守卫、错误边界)以及测试
脚手架都得自己写——那些"私有约定"每个新加入的人和模型都要从头学一遍,而且随应用
长大一定会悄悄漂移。

Nest 把它们作为一份固定且成文的契约交给我们:声明式模块图由容器在启动时解析,
缺依赖在启动就失败,而不是等到第一个请求;唯一的请求管道,顺序永远不用重新发明;
内建的 schema 校验与序列化;以及一套能装出真实模块图的测试工具。

这些都不是我们自造的,它们的形状正是整个生态——以及写代码的模型——已经熟稔的
那一套。它还能直接迁移到 Spring Boot:模块 ≈ 组件扫描,provider ≈ Bean,
guard/pipe/interceptor ≈ filter/validator/interceptor。
