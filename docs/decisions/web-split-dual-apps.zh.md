# 为什么把 Web 拆成两个应用

[English](web-split-dual-apps.md) | 简体中文

## 核心思路

理由就两条:

**一,各自演化。** PC 端和移动端各自发展,改一端完全不用考虑另一端。移动端想把某个页面改成纯对话式,直接改 `apps/web-mobile`,PC 端零感知。

**二,比响应式灵活。** 不用在同一份代码里用断点类兼顾两种形态,每端的布局和交互想怎么做就怎么做。

仅此而已。

## 怎么拆

```text
apps/
├── web/             # PC 端,入口 /
├── web-mobile/      # 移动端,入口 /m/
packages/
└── contract/        # 两端共享:API 客户端、类型、纯逻辑
```

两端真正需要一致的,只有对服务端的契约——放进 `@toby/contract`。界面、组件、样式各端自有,不共用。

## 本仓库的实现约束

- 两个应用互不导入,由 ESLint 强制。
- 共享只经 `@toby/contract`,它永远零组件、零样式。
- 依赖方向永远 `apps → packages`;Web 应用不导入 `@toby/server`。
- 同源部署:`/` 与 `/m/` 由 server 单进程分发,会话共享。
