# 个人智能体的记忆

[English](personal-agent-memory.md) | 简体中文

Toby 是个人管家,而管家的记忆是活的:不等你吩咐就会学,失效了就会忘,每一次变化都向你播报。整个域由一条原则统摄——**AI 有权记、有权忘,但每次变化都留回执,用户随时可以用一句话否决任何一条。** 存储是一个文法严格的 Markdown 文件,躲在 `MemoryStore` 端口后面;读路径按"遗忘的代价"分级:约定常驻每个 agent 的脑中,人物与事实则是一行常驻索引加按需回想。

## 为什么

- **定位要求活记忆。** 用户原话:更重要是可以忘记或删除失效记忆——更新只是及格线,*会忘*才是功能。只增不减的记忆是档案室,管家要修剪。
- **本分支的第一稿是 explicit-only**——用户不亲口说就不存,条目元数据照搬 Today 文章的治理框架。那读起来像个可配置工具,不像管家:不教就不会。该稿由本文替换。文章的逐条元数据保留下来(映射见下),并从装饰变成承重结构:静默学习之下,来源和状态终于真正干活。
- **既有写规则一寸不让。** 每次记忆变化仍然是确定性验证加一次原子存储写,走 write-intent 工具,带回执。变的只有触发者——agent 自己的观察,而不是用户的句子——以及问责方式:从确认门挪到回执。

## 治理模型

| 动作   | 谁发起                                    | 用户看到什么                                            |
| ------ | ----------------------------------------- | ------------------------------------------------------- |
| 学     | agent,不请自来,对话进行中                 | 已记住:咖啡记「饮品」                                   |
| 更新   | 一句矛盾的话,或 agent 自己察觉矛盾        | 带 before/after 的回执——替换,不并存                     |
| 忘     | 到期(`至` 某日)、用户的话,或 agent 的清理 | 已清理:出差上海记「差旅」(已过期 10 天)                 |
| 否决   | 用户,永远                                 | 一句话改写或删除任何一条——且删除是持久的(否决清单,见下) |
| 不入册 | 用户——一句话(这通别记)或页面开关          | 该会话内 policy 门拒绝一切 remember / forget 调用       |

中间方案——察觉后请示,要我记下来吗?——被否决了:确认门在这个产品的任何地方都不存在,而管家的姿态是我记下了,不是我可以记吗。代价是明知而接受的:一条学错的记忆会影响下一次写,直到被划掉。安全网是回执(每次变化可见)、一句话否决,和记忆页。

**否决是持久的。**静默学习让“删除”只剩半个动词:今天删掉的条目,下个月同样的纠正模式再来一遍,它又被学回来。所以用户删除会同时写入否决清单(store 的内部状态——不注入、不渲染为记忆),学习路径对它做验证:命中清单的候选条目直接拒绝,想再学,要用户亲口重新发起。遗忘的镜像是不再学。

## 条目:三种类别,每条一行

```markdown
## 约定

- 咖啡记「饮品」 [2026-11-11]
- 出差期间餐饮记「差旅」 [2026-11-03 至 2026-11-30]

## 关于我

- 不吃香菜 [2026-11-11]
- 在减脂 [2026-11-08 待确认 源#3f2a]

## 人物

- 小王:房东 [2026-09-15]
```

文法:一条一行;`[日期]` 必填;`至 日期`、`待确认`、`源#引用` 是可选标记;人物条目以 `人名:` 开头。解析器是确定性的,属于验证的一部分——解析不了的行,整个写入被拒绝。

| 字段    | 现在落在哪                                                                                            |
| ------- | ----------------------------------------------------------------------------------------------------- |
| kind    | 节标题——同时编码效力与可见范围(见下)                                                                  |
| status  | `待确认` 标记;无标记 = 已确认                                                                         |
| subject | 人物:开头的名字;关于我:用户本人;约定:规则本身                                                         |
| text    | 行正文,一句话                                                                                         |
| 时间    | `[日期]`——最近一次确认                                                                                |
| until   | `至 日期`——到期;过期条目在任何地方都不再出现                                                          |
| origin  | `源#引用`——聊天条目的短引用,页面渲染成跳回"教它这条的那次对话"的链接。静默学来的条目必带,显式条目不带 |
| id      | 没有——全文原子替换不需要 id                                                                           |

status 不改变效力:静默学来的约定立即生效——这正是静默学习的本意。它管的是显示(页面上的待确认标记)和遗忘力度(agent 清理未确认推断可以比清理已确认事实更激进)。

| 类别   | 效力                                                           | 谁能看到              |
| ------ | -------------------------------------------------------------- | --------------------- |
| 约定   | **服从**——可以改写记账草稿(咖啡→饮品);冲突时眼前这句话仍然优先 | 所有写域 + 意图分类器 |
| 关于我 | 只影响回答                                                     | 聊天                  |
| 人物   | 帮助指认和归因(小王=房东);绝不自行给出金额或日期               | 聊天 + 记账           |

文章的七个元数据字段干净地映射过来:主体→kind+subject,来源→origin(转述的归属留在正文里,小王说他…),状态→status,时间→日期,范围→kind 的可见范围,保留→until + 清理权,行动影响→效力。事件(已发生事件)不是一种类别——事件归 notes 和聊天历史;记忆只存没有域认领的稳定背景。

## 存储:一个文法严格的 Markdown 文件,躲在端口后面

- `data/memory/MEMORY.md` 仍是全库唯一的非数据库存储——[一域一库](db-adapter.zh.md)的记录在案的例外——但现在有了退出路径。
- **`MemoryStore` 端口先行。** 域代码(service、工具、验证、回执)面向端口编译;今天唯一的实现是 Markdown 文件,数据库适配器将来在 composition root 里替换它,域代码零改动。
- **严格文法就是迁移路径。** 将来的 db 导入是一次性的 parse → build → 条数核对——正因为每行都可解析,这才可行。
- 一次写 = 一次全文原子替换(临时文件 + rename)。欢迎手编——走页面的编辑器或直接改磁盘文件——但解析不了的文件会被拒绝,绝不静默修复。
- 页面的导出是按需生成的 `.md` 快照。不做常驻投影文件:同步的影子文件迟早变成第二真源,手编内容会被下一次写入冲掉。

## 读路径:按遗忘的代价分级

把条目按"被用到的频率"排序:约定是头部——少,每条都承重;人物和事实是长尾——单条少用,总量无界。机制强度对准失败代价:

| 层                   | 机制                                                   | 为什么是它,不多不少                                                                                                                                                         |
| -------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 约定                 | **全量注入**到每个写域的 prompt 和意图分类器           | 漏一条约定 = 一笔静默的错账——验证通过、回执打印、无人知晓。paraphrase(拿铁之于咖啡)只有约定在场时模型自己能接上;让它自己组查询词则搜不到。清理权压着总量,常驻的代价只有几行 |
| 人物,写路径上        | **确定性预取**:句子的分词与已解析条目做匹配,命中项注入 | 人名是精确 token——字面匹配几乎不失手;零模型成本,零额外往返                                                                                                                  |
| 人物 + 关于我,聊天中 | **常驻索引 + recall 工具**                             | 渐进披露:清单常驻 prompt,正文按需加载——与运行时已在用的 skill 同构(name+description 常驻,SKILL.md 按需加载)                                                                 |

每个 agent 携带的 `<memory>` 段:

```text
<memory>
## 约定
- 咖啡记「饮品」
- 出差期间餐饮记「差旅」 (至 11-30)

## 记忆索引 — 详情用 recall 工具查询
人物: 小王、妈妈     关于我: 饮食、作息
</memory>
```

- `recall` 是 read-only 工具——对已解析条目做关键词匹配。没有向量,没有检索基础设施:模型自己是检索器,工具只是"翻本子"的动作。它的 prompt snippet 按 skill description 的规范写成路由信息(什么时候用),不是"查询记忆"这种光标签。
- 过期条目哪里都不出现:不注入、不预取、不被 recall 返回。页面把它们沉底、标日期,等续期或删除。
- **不设强制门。** "没有 recall 过就拒绝 submit_entries"的闸门能保证回想这个动作,保证不了回想的对象,且每笔写多一轮模型往返。traces 已经记录 recall 调用;第一次观察到的"该回想没回想"案例,决定哪个 agent(如果有)配得上这道门。

## 写路径

- 三个工具:`recall`(read-only)与 `remember` / `forget`(write-intent)。聊天 agent 的策略从只读放宽为只读 + 记忆写——第一个记账之外的 write-intent agent。
- 每次写:确定性验证(文法、日期、替换还是去重、上限、否决清单)→ 一次原子存储写 → 回执卡片,更新带 before/after。回执骑在现有卡片机器上,不发明新东西。
- 上限是几百行量级的硬后盾:满了就是拒绝加一句"该忘点什么?"——绝不静默截断,绝不自动摘要。
- 显式的记忆句子(记住X / 忘掉X / 你记得我什么)像任何域一样走[聊天能力注册](chat-domain-capabilities.zh.md)路由;静默学习不需要路由——工具搭上当时正在跑的任何一个 agent。

## 永不存储

- **凭据**——密码、验证码、支付信息。记忆随每次运行发给模型供应商,永远不能装秘密。
- **事件与逐字记录**——归 notes 和聊天历史。
- **域自己拥有的东西**——截止日期、待办、账目行;记忆若复制它们,就会变成文章说的"有打断权力的陈年旧物"。

## 记忆页

按类别分组的 Markdown 文档——管家的备忘录,不是数据库表格。每条可:确认(清掉待确认)、编辑、删除;过期条目沉底标日期;源# 跳回教它这条的对话;导出为 `.md`。

## 九问自检

文章的验收清单,按本设计作答——并且重新作答,因为静默学习改掉了其中两问的答案:

| #   | 问题                              | 答案                                                                                                                                  |
| --- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 能看到具体记忆,而非模型口头总结?  | 能——页面渲染的就是 MEMORY.md 本体;「你记得我什么」逐条原文列出                                                                        |
| 2   | 来源与最近确认时间?               | 源# 跳回教学对话;每条带最近确认日期                                                                                                   |
| 3   | 标为临时、设到期、限范围?         | 到期有(至);范围只到 kind 粒度——按条目定范围刻意不建                                                                                   |
| 4   | 纠正后旧版本不再生效?             | 替换,绝不并存;回执带 before/after                                                                                                     |
| 5   | 删除记忆,连同重新生成它的来源?    | 删除 + 否决清单——被删条目不会被静默重学;想再学要用户明确发起                                                                          |
| 6   | 让某段对话从一开始就不进记忆?     | 能——会话开关(一句话或页面开关),policy 门在该会话拒绝一切 remember / forget 调用                                                       |
| 7   | 工作/家庭/人物语境隔离?           | 单用户单一语境,by design;人物按 subject 分组                                                                                          |
| 8   | 解释某条记忆何时影响了建议或行动? | 部分——traces 实时显示每次运行的完整 prompt(含 <memory> 与 recall 调用),但刻意不留存;回执隐含影响(你没说「饮品」它记了饮品),不解释影响 |
| 9   | 执行动作仍经权限/批准?            | 记忆从不发起或授权写;一切写仍是确定性验证 + 一次事务 + 回执——以验证替代批准,是本产品的一贯立场                                        |

## 刻意不建

定期整理(greeting 域的天然职责,以后)· 按条目定范围 · 语义/向量检索 · 重新确认提醒 · 强制回想门。

## 测试

本仓库惯例:临时数据根、脚本化 AI、生产 `data/` 一个字节不动。文法解析器单元测试；经 faux agent 的写路径测试（学 → 回执；矛盾 → 带 before/after 的替换；过期 → 沉底；超限 → 拒绝并询问；否决 → 重学被拦；不入册会话 → 工具被拒）；注入、预取、索引的按类别断言；真模型的 记住 → 使用 → 纠正 → 遗忘 全流程是手工步骤，需明确授权。
