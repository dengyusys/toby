# 个人智能体的记忆

[English](personal-agent-memory.md) | 简体中文

Toby 是个人管家,而管家的记忆是活的:不等你吩咐就会学(即静默学习),失效了就会忘,每一次变化都向你播报。整个域由一条原则统摄——**AI 有权记、有权忘,但每次变化都留回执(一张写明改了什么的小卡片),用户随时可以用一句话否决(改掉或删掉)任何一条。** 存储是一个格式严格的 Markdown 文件,躲在仓库(repository)端口后面;怎么读按"遗忘的代价"分级:约定永远摆在每个 agent 眼前,人物与事实则是一份目录加按需回想。

## 为什么

- **定位要求活记忆。** 用户原话:更重要是可以忘记或删除失效记忆——更新只是及格线,*会忘*才是功能。只增不减的记忆是档案室,管家要修剪。
- **本分支的第一稿是 explicit-only**——用户不亲口说就不存,条目元数据照搬 Today 文章的治理框架。那读起来像个可配置工具,不像管家:不教就不会。该稿由本文替换。文章的七个元数据字段只有压着机制的四个落地(映射见下);来源、状态、逐条时间刻意不落地——记忆不依赖来源而成立,静默学习的问责靠当时的回执与 traces,不靠行内留底。
- **既有写规则一寸不让。** 每次记忆变化仍然是确定性验证加一次原子存储写,走 write-intent 工具(带写权限、调用前要过 policy 门检查的那类),带回执。变的只有触发者——agent 自己的观察,而不是用户的句子——以及问责方式:从确认门挪到回执。

## 治理模型

| 动作   | 谁发起                                    | 用户看到什么                                      |
| ------ | ----------------------------------------- | ------------------------------------------------- |
| 学习   | agent,不请自来,对话进行中                 | 已记住:咖啡记「饮品」                             |
| 更新   | 一句矛盾的话,或 agent 自己察觉矛盾        | 带 before/after 的回执——替换,不并存               |
| 遗忘   | 到期(`至` 某日)、用户的话,或 agent 的清理 | 已清理:出差上海记「差旅」(已过期 10 天)           |
| 否决   | 用户,永远                                 | 一句话改写或删除任何一条;页面上有同样的按钮       |
| 不记忆 | 用户——一句话(这通别记)或页面开关          | 该会话内 policy 门拒绝一切 remember / forget 调用 |

中间方案——察觉后请示,要我记下来吗?——被否决了:确认门在这个产品的任何地方都不存在,而管家的姿态是我记下了,不是我可以记吗。代价是明知而接受的:一条学错的记忆会影响下一次写,直到被划掉。安全网是回执(每次变化可见)、一句话否决,和记忆页。

**删除就是删除,不是封禁。**静默学习意味着今天删掉的条目,下个月同样的模式再现时可能被重新学回——没有任何隐藏机制去阻止,这是刻意的。否决清单考虑过、被放弃:它会是整个产品唯一一处看不见的永久状态,而且承诺本来就守不住——精确匹配挡不住换个说法(不吃香菜 → 讨厌香菜),语义匹配又需要本设计明确拒绝的检索基础设施。防线用产品本来就信任的那两样:每次重学都留回执,一句话可以再删。「这类事根本别记」是不记忆开关的职责;按主题的屏蔽,等首次观察到「删了又学」成环再说。

## 条目:三种类别,每条一行

```markdown
## 约定

- 咖啡记「饮品」
- 出差期间餐饮记「差旅」 (至 2026-11-30)

## 关于我

- 不吃香菜
- 在减脂

## 人物

- 小王:房东
```

格式:一条一行;行尾可选 `(至 日期)`,再无其他标记;人物条目以 `人名:` 开头。解析器是确定性的,属于验证的一部分——解析不了的行,整个写入被拒绝。

| 字段 | 现在落在哪                                         |
| ---- | -------------------------------------------------- |
| 类别 | 节标题——同时决定这条记忆起什么作用、谁能看到(见下) |
| 主体 | 人物:开头的名字;关于我:用户本人;约定:规则本身      |
| 正文 | 行正文,一句话                                      |
| 到期 | `(至 日期)` 标记;过期条目在任何地方都不再出现      |

status、origin、逐行日期、id 刻意不落地——记忆不依赖来源而成立。行内只留压着机制的标记:没有到期标记就没有确定性的遗忘;而问责与新鲜度,学时的回执和 traces 当场就承担了,行内留底等于为三天后的追问买一份永远要维护的保险。代价是明知而接受的:事后在页面上看到一条没教过的记忆,跳不回教它的那次对话,只能翻聊天记录,也看不出它多老了。

| 类别   | 起什么作用                                                     | 谁能看到                                      |
| ------ | -------------------------------------------------------------- | --------------------------------------------- |
| 约定   | **服从**——可以改写记账草稿(咖啡→饮品);冲突时眼前这句话仍然优先 | 所有会写库的域 + 意图分类器(判一句话归哪个域) |
| 关于我 | 只影响回答                                                     | 聊天                                          |
| 人物   | 帮着认人(小王=房东);绝不自行给出金额或日期                     | 聊天 + 记账                                   |

文章的七个元数据字段落地四个:主体→类别+人名前缀,范围→类别决定谁能看到,保留→到期标记+清理权,行动影响→起什么作用;转述的归属留在正文里(小王说他…)。事件(已发生事件)不是一种类别——事件归 notes 和聊天历史;记忆只存没有域认领的稳定背景。

## 存储:一个格式严格的 Markdown 文件,躲在端口后面

- `data/memory/MEMORY.md` 仍是全库唯一的非数据库存储——[一域一库](db-adapter.zh.md)的记录在案的例外——但现在有了退出路径。
- **仓库端口先行。** 域代码(service、工具、验证、回执)面向 repository 编译,与 chat、ledger 的叫法一致;今天唯一的实现是 Markdown 文件,数据库适配器将来在 composition root 里替换它,域代码零改动。
- **严格格式就是迁移路径。** 将来的 db 导入是一次性的 parse → build → 条数核对——正因为每行都可解析,这才可行。
- 一次写 = 一次全文原子替换(临时文件 + rename)。欢迎手编——走页面的编辑器或直接改磁盘文件——但解析不了的文件会被拒绝,绝不静默修复。
- 页面的导出是按需生成的 `.md` 快照。不做一直同步的投影文件:影子文件迟早变成第二真源,手编内容会被下一次写入冲掉。

```text
apps/server/src/domains/memory/     # 域代码:垂直切片,不依赖其他域
├─ plugin.ts                        # 域组装:路由、工具、policy 注册
├─ errors.ts                        # 本域错误码(封闭联合)
├─ types.ts                         # 纯类型:条目、解析结果
├─ parser.ts                        # 逐行解析与序列化——确定性,验证的一部分
├─ repository.ts                    # 仓库:记忆的读与验证过的写都归它(端口)
└─ memory-file.ts                   # 记忆域的 db.ts:唯一碰磁盘的文件——读写 MEMORY.md,临时文件 + rename 原子替换

data/memory/
└─ MEMORY.md                        # 唯一的存储;欢迎手工编辑,解析不了会被拒绝
```

## 怎么读:按遗忘的代价分级

把条目按"被用到的频率"排序:约定是头部——少,每条都承重;人物和事实是长尾——单条少用,总量无界。机制强度对准失败代价:

| 层                   | 机制                                           | 为什么是它,不多不少                                                                                                                                                             |
| -------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 约定                 | **全部写进**每个会写库的域和意图分类器的提示词 | 漏一条约定 = 一笔静默的错账——验证通过、回执打印、无人知晓。paraphrase(拿铁之于咖啡)只有约定在场时模型自己能接上;让它自己组查询词则搜不到。清理权压着总量,常在眼前的代价只有几行 |
| 人物,写库时          | **在句子里找已记的人名**,命中的条目直接带上    | 人名是精确 token——字面匹配几乎不失手;零分词、零模型成本、零额外往返;误命中(小王撞小王子)接受,消歧是模型的活                                                                     |
| 人物 + 关于我,聊天中 | **目录留在提示词里,正文用 recall 现查**        | 与运行时已在用的 skill 同构:目录常在提示词里(name+description),正文按需加载(SKILL.md)                                                                                           |

每个 agent 携带的 `<memory>` 段:

```text
<memory>
## 约定
- 咖啡记「饮品」
- 出差期间餐饮记「差旅」 (至 11-30)

## 记忆索引 — 详情用 recall 工具查询
人物: 小王、妈妈     关于我: 饮食、作息
</memory>
```

- `recall` 是 read-only 工具——对已解析条目做关键词匹配,规则笨到底:子串命中、不区分大小写,匹配人名与行正文(类别标题与至 标记不参与);全类别都搜,过期条目不返回。换说法(拿铁之于咖啡)是模型的事——它自己换词多翻几次,工具不做任何展开。没有向量,没有检索基础设施:模型自己是检索器,工具只是"翻本子"的动作。它的 prompt snippet 按 skill description 的规范写成路由信息(什么时候用),不是"查询记忆"这种光标签。
- 过期条目哪里都不出现:不写进提示词、不预先带上、不被 recall 返回。页面把它们排在最后,等续期或删除。
- **不设强制门。** "没有 recall 过就拒绝 submit_entries"的闸门能保证回想这个动作,保证不了回想的对象,且每笔写多一轮模型往返。traces 已经记录 recall 调用;第一次观察到的"该回想没回想"案例,决定哪个 agent(如果有)配得上这道门。

## 怎么写

- 三个工具:`recall`(read-only)与 `remember` / `forget`(write-intent)。哪些 agent 带这些工具,划一条线:会话型 agent(聊天、记账,将来的 notes/todo 同理)一律都带——学约定的典型现场就是记账途中的纠正(咖啡改记「饮品」);意图分类器等一次性调用只得到 `<memory>` 段,无工具。聊天 agent 的策略从只读放宽为只读 + 记忆写——第一个记账之外的 write-intent agent。policy 门与回执按工具起作用,与哪个 agent 调用无关。
- 每次写:确定性验证(格式、至 日期、替换还是去重、上限)→ 一次原子存储写 → 回执卡片,更新带 before/after。回执复用现有的卡片组件,不发明新东西。
- 定位旧行:改/删不引用旧行原文,更没有 id——带一个关键词,用与 recall 完全相同的子串规则在人名+正文、未过期条目里找。恰好一条 → 替换或删除;多条 → 拒绝并逐条列出候选(解不开就问,绝不猜);零条 → forget 回"没有相关记忆",带替换的 remember 视为新增追加。不带替换关键词即纯追加,先查重——正文完全相同回"已记得:X"。回执的 before/after 就是命中行与新行。
- 上限是几百行量级的硬后盾:满了就是拒绝加一句"该忘点什么?"——绝不静默截断,绝不自动摘要。
- 显式的记忆句子(记住X / 忘掉X / 你记得我什么)像任何域一样走[聊天能力注册](chat-domain-capabilities.zh.md)路由;静默学习不需要路由——工具搭上当时正在跑的任何一个 agent。

## 记忆页

管家的备忘录,不是数据库表格——页面渲染的就是 `MEMORY.md` 本体,按类别分组,一屏读完。每条可编辑、删除;过期条目排在最后,等续期或删除;顶部导出 `.md` 快照。不记忆开关也在这里(治理表里的"页面开关"):打开后,本会话内一切 `remember` / `forget` 调用都被 policy 门拒绝。

## 九问自检

文章的验收清单,按本设计作答——并且重新作答,因为静默学习改掉了其中两问的答案:

| #   | 问题                              | 答案                                                                                                                                  |
| --- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 能看到具体记忆,而非模型口头总结?  | 能——页面渲染的就是 MEMORY.md 本体;「你记得我什么」逐条原文列出                                                                        |
| 2   | 来源与最近确认时间?               | 部分——学时回执当场可见;行内不留来源与时间,事后只能翻聊天记录                                                                          |
| 3   | 标为临时、设到期、限范围?         | 到期有(至);范围只到类别粒度——按条目定范围刻意不建                                                                                     |
| 4   | 纠正后旧版本不再生效?             | 替换,绝不并存;回执带 before/after                                                                                                     |
| 5   | 删除记忆,连同重新生成它的来源?    | 删除可以,再生成不拦——同样的模式再现时可能重学;靠可见性(重学必有回执)加一句话再删,不靠预防                                             |
| 6   | 让某段对话从一开始就不进记忆?     | 能——会话开关(一句话或页面开关),policy 门在该会话拒绝一切 remember / forget 调用                                                       |
| 7   | 工作/家庭/人物语境隔离?           | 单用户单一语境,by design;人物按人名分组                                                                                               |
| 8   | 解释某条记忆何时影响了建议或行动? | 部分——traces 实时显示每次运行的完整 prompt(含 <memory> 与 recall 调用),但刻意不留存;回执隐含影响(你没说「饮品」它记了饮品),不解释影响 |
| 9   | 执行动作仍经权限/批准?            | 记忆从不发起或授权写;一切写仍是确定性验证 + 一次事务 + 回执——以验证替代批准,是本产品的一贯立场                                        |
