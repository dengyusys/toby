# 个人智能体记忆

[English](personal-agent-memory.md) | 简体中文

Toby 是个人管家，管家的记忆是活的：不问自取地学习（即静默学习），忘掉不再为真的事，并汇报每一次变化。整个域由一条原则统治——**AI 可以记、可以忘，但每次变更都留一张回执（说明改了什么的小卡片），用户一句话能否决——改写或删除——任何一条记忆。** 存储是仓储端口背后的一个严格解析的 Markdown 文件，按开放的主题小节组织，一律平等。读取只有一条规则：**整本书永远摊开**——每一条、每一节，进每一个 agent 的提示词，由上限兜底。

> 第三版（本文）以开放小节和整本书规则取代三个固定类型（约定 / 关于我 / 人物）与分层读取（约定全文 + 索引 + recall）。动因：那三格是消费策略，不是内容分类——领域知识（转账规矩、工作惯例、健康）没有家，分层也无法生长。整本书是更简单、且自己会生长的机制。
>
> 第四版剪掉页面的写按钮。页面变成文件本身的只读视图——Markdown 原文——加一个维护控件：重置，两步确认清空整本书。写路径收敛为两条，各自对行动者诚实：AI 写走工具（off-record 门、回执）；人写靠手改文件，diff 就是回执。满是行内编辑器的页面是穿了备忘录外衣的数据库表；它的 REST 写路由是删除，不是封存。

## 为什么

- **定位要求活记忆。** 用户原话：更重要是可以忘记或删除失效记忆——更新只是底线，_忘记_ 才是功能。只累积的记忆是档案库；管家会修剪。
- **本分支初稿是显式记忆**——用户不要求就不存，元数据照搬 Today 文章的治理框架。它读起来像个可配置工具，不像管家：不教不会。那份草稿已被本版取代。文章七个元数据字段里只有带机制的四条存活（映射见下）；来源、状态、逐条时间刻意不落——一条记忆不需要记录自己从哪来，静默学习由发生当时的回执与 traces 交代，不靠文件内记账。
- **第三版的动因：记忆要能按领域生长。** 固定三格回答的是"谁看这条记忆"，回答不了"这条记忆是关于什么的"——报销规矩、作息事实、某人在转账里的角色，都得挤进以消费层级命名的格子里。用户定的产品方向：对话触及新领域（转账、工作、健康）时小节自然出现，文件按主题自组织，生活里冒出新领域时零代码变更。

## 治理模型

| 行动   | 谁发起                                       | 用户看到什么                                             |
| ------ | -------------------------------------------- | -------------------------------------------------------- |
| 学习   | agent，对话中不问自取                        | 已记住:咖啡记「饮品」                                    |
| 更新   | 一句矛盾的话，或 agent 自己察觉              | 带 before/after 的回执——替换，绝不共存                   |
| 忘记   | 到期（`至` 日期）、用户的话、或 agent 的清理 | 已清理:出差上海记「差旅」(已过期 10 天)                  |
| 否决   | 用户，随时                                   | 一句话改写或删除任何一条；手改文件同理                   |
| 重置   | 用户，从页面发起                             | 一次原子写清空整本书（`{reset_at}`）；不过 off-record 门 |
| 不记录 | 用户——一句话（这通别记）或页面开关           | 策略门在该会话内拒绝每一次 remember / forget 调用        |

中间选项——注意到并询问，要我记下来吗？——被否决：确认门在这个产品里无处存在，管家的姿态是我记下了，不是我可以记吗。代价是有意识接受的：错学的一条会影响下一次写入，直到被划掉。安全网是回执（每次变更可见）、一句话否决、以及页面。

**删除就是删除，不是封禁。** 静默学习意味着今天删掉的一条，下个月同一模式再现时可能被重新学回——没有任何隐藏机制阻止这一点，这是刻意的。否决台账考虑过并放弃：它会成为产品唯一一块不可见的永久状态，而且也守不住承诺——精确匹配被改写绕过（不吃香菜 → 讨厌香菜），语义匹配需要本设计拒绝的检索基础设施。防线是产品已经信任的那些：每次重学都留回执，一句话再删一次。"彻底别再注意这个"是 off-record 开关的事；按主题封禁等第一次真的观察到删了又学的循环再说。

## 条目：开放小节，一行一条

```markdown
## 约定

- 咖啡记「饮品」
- 出差期间餐饮记「差旅」 (至 2026-11-30)

## 关于我

- 不吃香菜

## 转账

- 给小王的转账走「人情往来」

## 工作

- 公司报销必须要有发票

## 人物

- 小王:房东
```

格式：`## <主题>` 标题，其后一行一条；唯一可选的尾标记是 `(至 日期)`，再无其他。`约定`、`关于我`、`人物` 不是特殊的——它们只是最初几次写入产生的主题，留作家常用词。人物类条目保持 `名字:描述` 的写法，是家规不是语法。解析器是确定性的，且是校验的一部分——解析不了的行拒绝写入。小节名自由（非空、简短、全文件唯一）；重复的标题非法——该合并。

| 字段   | 落在哪                              |
| ------ | ----------------------------------- |
| 主题   | 小节标题——这条记忆是关于什么的      |
| 正文   | 行体，一句话                        |
| 保留至 | `(至 日期)`——过期；过期条目处处消失 |

状态、来源、逐条时间、id 刻意不落——一条记忆不需要记录自己从哪来才算有效。文件只留带机制的标记：没有 保留至 就没有确定性的遗忘；当责与新鲜度由学习当时的回执和 traces 现场处理——文件内记账是给三天后的问题上的保险，却要永远维护。代价是有意识接受的：一条你没教过的记忆无法链回学到它的那通对话——只能翻聊天史——它的年龄不可见。

事件（已发生事件）不是主题——笔记和聊天史拥有事件；记忆只持有没有任何域认领的稳定背景。未来某个域（日程、笔记）要自己的记录就建自己的库；这里的小节是背景知识，不是台账。

## 存储：端口背后的一个严格 Markdown 文件

- `data/memory/MEMORY.md` 仍是唯一的非数据库存储——[一域一库](db-adapter.md) 的在案例外——且留了退路。
- **仓储端口优先。** 域代码（service、tools、校验、回执）面向仓储编程，与 chat、ledger 用同一个词；Markdown 文件是它今天唯一的实现，将来数据库适配器在 composition root 一换即可，域代码不动。
- **严格格式就是迁移路径。** 将来入库是一次性的 解析 → 构建 → 对数——正因为每行都可解析才可行。
- 一次写 = 一次整文件原子替换（临时文件 + rename）。欢迎手改——直接改文件——但不再可解析的文件会被拒绝，绝不静默修复。
- 没有导出功能：页面展示的就是文件本身，备份就是拷贝磁盘上的文件（服务器是用户自己的）。没有任何第二个文件镜像这份存储——常驻同步的导出会成为第二真相源，而且对它的手改会在下次写入时被抹掉。

```text
apps/server/src/domains/memory/     # 域代码：垂直切片，无跨域导入
├─ plugin.ts                        # 域装配：路由、工具、策略注册
├─ errors.ts                        # 本域错误码（封闭联合）
├─ types.ts                         # 纯类型：条目、解析结果
├─ parser.ts                        # 逐行解析与序列化——确定性，属于校验的一部分
├─ repository.ts                    # 仓储：记忆的读取与校验后的写入（端口）
└─ memory-file.ts                   # 本域的 db.ts：唯一碰磁盘的文件——读写 MEMORY.md，临时文件 + rename 原子替换

data/memory/
└─ MEMORY.md                        # 唯一存储；欢迎手改，不可解析即拒绝
```

## 怎么读：整本书，永远摊开

一条规则，没有分层：**每一节的每一条未过期条目，写进每一个 agent 的 `<memory>` 提示词小节——聊天、每个写库的抽取器、意图分类器、记忆 agent——每次运行现场解析。** 管家每次出门都揣着整本笔记，像人一样。

```text
<memory>
## 约定
- 咖啡记「饮品」
- 出差期间餐饮记「差旅」 (至 11-30)

## 关于我
- 不吃香菜

## 转账
- 给小王的转账走「人情往来」

## 人物
- 小王:房东
</memory>
```

为什么放弃分层，以及整本书规则的代价：

- **那些层是冒充内容分类的消费层级。** 约定全文是为了防静默错写（漏一条约定）；索引加 recall 的长尾是为了省提示词。但层级无法生长——每个新主题都要定一条层级策略——而决定相关性的一直是模型，不是文件。
- **在场性现在严格更强。** 旧设计里只有约定到达写路径；整本书摊开后，写库 agent 写的时候也看得见 人物、转账、健康。静默错写这一类问题失去的是成因，不只是个例。名字命中注入机制（句子里字面查记住的名字）同理退役——名字本来就在提示词里，命中与否都在。
- **`recall` 退役。** 这个工具存在的意义是翻一本提示词里只有索引的书；书在手上了，它没有可取的东西。你记得我什么 由模型对着书逐条照抄作答。检索基础设施不复存在——模型是检索器，现在也是书页。
- **代价，有意识接受：** 提示词 token 随书增长（每条约 20 token；100 条 ≈ 2K，500 上限 ≈ 10K），每次运行都要付，包括意图分类器；稳定的前缀让提供方的提示词缓存吃掉大半。无关的行会搭车——每条是一行自描述的句子，噪声有界，误用（记账时被一条转账规矩带偏）是模型该忽略而没忽略的失败，traces 里看得见，一句话否决可纠正。上限从"绰绰有余"升格为"书的实际边界"——满了就是拒绝加一句 该忘点什么，绝不静默截断，绝不摘要。
- 过期条目不进提示词；在只读页面上它们就是文件自身的行，等待续期或删除。
- 损坏的文件把小节降级为可见占位符（记忆文件当前无法读取）——聊天照常，记忆保持可见的坏。

## 怎么写

- 三个工具：`remember` / `forget`（写意图）和 `off_record`。谁带它们遵循一条线：每个会话型 agent（chat、ledger、以及将来的笔记/待办）带 remember 和 forget——规矩最常学到的地方是记账时的纠正（咖啡改记「饮品」）——而 `off_record` 留在记忆域自己的 agent 上，服务显式的 这通别记 / 可以记了。意图分类器这类一次性调用方拿到 `<memory>` 小节但没有工具。策略门和回执作用在工具上，与哪个 agent 调用无关。
- 写路径收敛为两条，只有两条：AI 写走工具（过 off-record 门、留回执）；人写靠手改文件——或从页面重置，一次原子清空，不过 off-record 门、文件损坏时也允许（显式丢弃是修复通道，不是静默修复）。页面表单时代的写端点已删除，不留无消费者的接口。
- **选小节是模型的第一判断：** 优先归入明显所属的既有小节；确实都不搭才开新节；用户的显式指令（记到「工作」里）永远优先。小节野蛮生长（转账 vs 金钱）是接受的失败模式——手改文件是解药，提示词守则让它保持罕见。
- 每次写入：确定性校验（格式、至 日期、替换对重复、小节名规则、上限）→ 一次原子存储写 → 回执卡，更新带 before/after。回执复用既有卡片组件；不发明新东西。
- 定位旧行：更新或删除不带旧行原文、不带 id——带一个关键词，对全部未过期条目正文做子串匹配。恰好一条命中 → 替换或删除；多条 → 拒绝并列出候选（解不开就问——绝不猜）；零条 → 忘掉 回答"没有相关记忆"，带替换的 remember 当作新追加。不带替换关键词的 remember 是纯追加，先对整本书查重——任何地方有相同文本就回答"已记得：X"。回执的 before/after 就是命中行和新行。
- 500 条硬上限：满了就是拒绝加一句该忘点什么。
- 显式记忆句（记住X / 忘掉X / 你记得我什么）像任何其他[聊天能力](chat-domain-capabilities.md)一样路由到记忆域；静默学习不需要路由——工具搭上正在运行的那个 agent。

## 记忆页面

管家的备忘录，不是数据库表——页面渲染的就是 `MEMORY.md` 本身：Markdown 源文本、等宽字体、按文件序，磁盘上的文件一字不差；空文件显示空态，损坏的文件显示诚实的错误。页面上没有任何编辑：改动是聊天一句话或手改文件。保留两个控件——记忆开关（开启记忆 / 关闭记忆；治理表里的"页面开关"：关闭期间，该会话内每一次 remember / forget 调用都被策略门拒绝）、重置：两步确认（条目数、不可撤销提醒）后一次原子写清空整本书，文件损坏时也允许。

## 九问检验

文章的验收测试，按本设计作答——重新作答，因为开放小节改了两处答案：

| #   | 问题                           | 回答                                                                                                                   |
| --- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 1   | 看到真实条目，不是模型摘要？   | 是——页面逐字展示 MEMORY.md 源文件；你记得我什么 对着摊开的书逐条照抄                                                   |
| 2   | 来源与最后确认时间？           | 部分——学习当时的回执现场可见；文件里不存来源链接和时间戳；事后追溯只能翻聊天史                                         |
| 3   | 标记临时、设期限、限范围？     | 期限有（至）；范围按主题小节——小节就是范围，而小节是自由的                                                             |
| 4   | 改对了，且旧版本停止生效？     | 替换，绝不共存；回执展示 before/after                                                                                  |
| 5   | 删除，包括再生源头？           | 删除有，再生不拦——同一模式可重学；可见性（每次重学留回执）加一句话删除，而非阻止                                       |
| 6   | 有一通永不进入记忆的对话？     | 有——会话开关（一句话或页面开关）让策略门拒绝每一次 remember / forget 调用                                              |
| 7   | 工作/家庭/人物隔离？           | 单用户、单上下文，by design；主题就是分组，名字由用户取                                                                |
| 8   | 记忆影响了回答或行动时能解释？ | 部分——traces 现场展示每次运行的完整提示词，记忆在内，但刻意不存储；回执暗示影响（你从没说过的 记入「饮品」）而不解释它 |
| 9   | 行动仍需许可？                 | 记忆从不发起或授权写入；每次写入仍是确定性校验 + 一个事务 + 一张回执——以校验代替审批，产品一贯立场                     |
