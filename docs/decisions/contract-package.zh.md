# 为什么要有 @toby/contract 这个包

[English](contract-package.md) | 简体中文

## 核心思路

两个 Web 应用调的是同一个服务端。**API 客户端、类型、请求逻辑,两份代码必须完全一致——那就只留一份。**

`@toby/contract` 就是这一份:双端共享的契约包。

## 解决什么问题

不共享的话,每个应用要自己维护一套请求与类型:

- 接口改了要记得改两处;忘一处,另一端在运行时才炸
- 同一个概念两个类型定义,时间长了互相漂移
- 契约没有单一事实来源

放进一个包,契约变了只改一处,两端同时生效。

## 为什么必须是纯逻辑

这个包有一条硬规矩:**零 JSX、零 CSS、零 DOM。**

- 它只回答"怎么跟服务端说话":API 客户端、类型、请求封装、提案流程、纯函数
- 界面归各应用(见双应用拆分):组件和样式是呈现,呈现本来就分叉
- 这条规矩防它变成杂物抽屉——什么都往共享包塞,两端就被它拴回一起,应用白拆了

## 怎么消费

- workspace 包,双端以 `apps → packages` 方向依赖
- 深路径 + `.ts` 直接消费源码,不构建、不发布
- 端上用到的服务端类型只在这里定义一次

## 本仓库的约定

- 跨端共享只经 `@toby/contract`,它永远零组件、零样式
- 依赖方向永远 `apps → packages`;包不导入应用,应用互不导入
- 契约变更只改这个包,两个应用同时生效
