# 首次注册:密码存在认证数据库里

[English](first-run-registration.md) | 简体中文

所有者在首次启动时于一次性的注册页面上设置登录密码,哈希存在认证数据库里。没有免登录模式,也没有密码环境变量。

**理由:旧做法把凭据绑在部署配置上 —— 用脚本生成哈希、粘进 `.env`、改密码要编辑文件再重启 —— 而没配它的服务器所有路由全开。登录系统应当自己管凭据:在产品里设置,随产品数据存储,在产品里修改。**

## 为什么

- **不再有默认敞开的服务器。**"未配置即免登录"让一个被遗忘的变量变成完全开放的 API。现在未配置的服务器是关闭的:所有者注册之前,什么都打不开。
- **凭据只在一处。** 哈希存在 `data/auth.db`,和其他域的数据放在一起 —— 同样的备份、同样的 `data/` 边界、同样只有 server 写入的规则。
- **没有秘密的交接。** 密码只经所有者自己的通道离开浏览器;没有需要生成、复制或发送的哈希。

## 模型

1. **一行记录。** `data/auth.db` 里有一张 `owner` 表,只有一行:scrypt 哈希与设置时间。会话留在内存里 —— 重启结束所有会话,密码保留。
2. **注册接口必须公开,它自己守住自己。** `POST /api/auth/register` 只在还没有密码、且服务端启动后十分钟内可用。这一行的主键是裁决者:第一次插入获胜,并发的第二次返回 `ALREADY_REGISTERED`。
3. **用时间窗口,不用设置码。** 在没人注册的服务器上,谁先打开页面谁就能设密码。十分钟把"忘了一天"变成"已关闭";重启会重新打开。被否决的方案是在控制台打印设置码 —— 它会把凭据放进日志,并给每次部署多加一步。
4. **不设默认密码。** 出厂默认值在没被改掉之前就是一个公开的凭据;服务器生成密码出于同样的理由被否决。
5. **硬切。** `TOBY_AUTH_PASSWORD_HASH` 不再被读取,也不会被导入:已有部署升级后需要重新注册。所有者选了它而不是一次性导入 —— 一次部署、一分钟的事,以后也不用清理遗留路径。

## 刻意不进第一版的

- **找回密码。** 忘记密码意味着停掉服务端、删除 `data/auth.db`、重新注册。没有脚本可以写数据库;只有 server 能写。
- **窗口时长可配。** 十分钟是常量。等出现第一个需要不同时长的部署再加变量。

## 测试

`app.inject` 配合注入的时钟驱动生产装配:窗口的最后一毫秒、窗口过期、重启后重新打开、只能注册一次,以及请求体的长度边界。根目录的 HTTP 集成测试在真实进程上注册,供每个需要 API 的测试组使用。
