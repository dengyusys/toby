# 长期记忆:一个 Markdown 文件

[English](memory-markdown-file.md) | 简体中文

Toby 有了长期记忆:一个 Markdown 文件——`data/memory/MEMORY.md`——里面是一小组有规矩的条目,全部是用户明确要求记下的。每个 agent 的提示词只带上它那个域需要的小节;每一次改动,不论是说出来的还是手动编辑的,都是一次经过校验、留有凭据的写入。设计依据是 Today 的文章[《个人智能体应该记住什么?》](https://today.ai/articles/zh-Hans/blog/what-should-ai-agent-remember):记忆需要规则,不只需要容量——难的从来不是容量,而是取舍和控制。

## 为什么

- **产品承诺是具体的。**"它记得你的偏好和习惯,越用越顺手"——对一个只有一句话输入的产品,"顺手"的意思是:同样的事,下次说得更短,照样落得准。记忆把一次性的纠正变成长期的约定:

  ```text
  你:咖啡 18             → 已记入:餐饮 ¥18
  你:不对,咖啡记饮品     → 已修改:餐饮 → 饮品
  你:以后都这样           → 记住了:〔约定〕咖啡记「饮品」
  (之后)你:咖啡 20      → 已记入:饮品 ¥20
  ```

  纠正只改了一行;约定让同样的纠正不必再发生。同理:打车都备注报销、「老规矩早餐」= 15 元、小王是房东。

- **治理规则就是 Toby 已有的承诺。** 写入摆在明面(凭据卡片),说不清就问、绝不猜,AI 不能自己行动。参考文章把同样的规矩说成记忆设计:一条记忆要有主体、来源、状态、时间、范围、保留规则和行动影响——取舍与控制重于容量。
- **用 Markdown 存,因为这是唯一一份用户必须能当普通文本读和改的数据。** 与 [Claude Code](https://code.claude.com/docs/en/memory)、[OpenClaw](https://docs.openclaw.ai/concepts/memory) 同一立场:纯文本文件就是唯一真相,磁盘上有什么,模型就知道什么——没有隐藏状态。

## 四层——Toby 已经有三层

| 层         | 在 Toby                                                                         | 现状     |
| ---------- | ------------------------------------------------------------------------------- | -------- |
| 当前上下文 | 用户这句话(以及分类器补全后的句子)加上今天的日期                                | 已有     |
| 历史记录   | `chat.db` 里的对话;只回放最近四轮、六小时以内                                   | 已有     |
| 任务状态   | **各业务域本身**——账目、(将来的)日程、待办、手账;各有自己的生命周期、存储和凭据 | 陆续落地 |
| 长期记忆   | `data/memory/MEMORY.md`                                                         | 本决策   |

边界由这张表推出:

- 进行中的目标、承诺和行动结果属于**业务域**:待办有完成状态,日程有时间,一笔账本身就是结果。记忆若重复存它们,就成了文章说的"拥有打扰能力的旧事项"。
- 原话的完整记录属于手账。
- 记忆只装**没有任何域拥有的稳定背景**——那些影响每个域如何理解一句话的上下文。

## 一条记忆:七个字段,三个类别

| 字段     | 在 Toby                                                                          |
| -------- | -------------------------------------------------------------------------------- |
| 主体     | 类别区分"我"与"人物";人物条目以人名开头                                          |
| 来源     | 条目只因用户说过才存在;关于他人的说法保留归属(「小王说…」)                       |
| 状态     | 约定(指令)或事实。**推断一律不入库**——agent 可以问"要我记下来吗?",明确同意才写入 |
| 时间     | 每条带最近确认日期                                                               |
| 范围     | 类别决定哪些域能看到                                                             |
| 保留规则 | 长期,或至某日                                                                    |
| 行动影响 | 由类别决定(见下)                                                                 |

| 类别   | 参考文章对应             | 例子                                                  | 保留                            | 行动影响                                 | 谁能看到             |
| ------ | ------------------------ | ----------------------------------------------------- | ------------------------------- | ---------------------------------------- | -------------------- |
| 约定   | 纠正与做事方式——明确指令 | 咖啡记「饮品」;打车备注「报销」;「老规矩早餐」= 15 元 | 直到用户修改                    | **可用于起草写入——照办**                 | 所有域 + 意图分类    |
| 关于我 | 稳定偏好与约束——确认事实 | 不吃香菜;回答要简短;每月 10 号发工资                  | 与当句矛盾时听当句,再问是否更新 | 只影响回答                               | 对话(以及将来的问候) |
| 人物   | 来源清楚的关系信息       | 小王:房东;妈妈:生日 3 月 12 日                        | 按原话存,不扩写成档案           | 帮助理解(分类、备注)——绝不提供金额和日期 | 对话、记账           |

**约定可以照办,事实只供参考。** 金额、日期、收支类型只来自这句话,除非某条约定明确定义了它们(「老规矩早餐」)。这句话与约定冲突时,这次写入听这句话的。校验与凭据原样不变——记忆不是权限。

任何一条都可以带有效期——即文章说的临时状态:「出差上海期间,餐饮记「差旅」(至 2026-11-30)」。过期的条目不再注入,在记忆页标为已过期,等用户续期或删除。没有任何东西被静默丢弃。

文件本身——小节标题用产品自己的语言:

```markdown
## 约定

- 咖啡记「饮品」 (2026-11-11)
- 出差上海期间,餐饮记「差旅」 (2026-11-03,至 2026-11-30)

## 关于我

- 不吃香菜 (2026-11-11)

## 人物

- 小王:房东 (2026-09-15)
```

## 一个文件——以及哪天该拆

- 整个文件按类别注入,没有检索,所以拆文件没有收益。类别是小节而不是文件,因为可见性是横切的:「人物」对话和记账都要读。
- 那些用多个文件的参照系,多出来的轴 Toby 都没有:Claude Code 跨组织/项目/用户多个作用域,且自动积累;OpenClaw 持续追加每日笔记,再从中精选出长期记忆;[Hermes Agent](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory) 把助手笔记和用户画像分成两份。Toby 是单用户、单实例、仅显式写入。
- **拆分条件,记录在案但不提前建:** 等无人值守的自动提炼落地,或上限涨到全量注入不再划算时,拆成"常驻注入的精选文件 + 按需读取的长尾文件"。今天的小节就是那道缝。
- 不设变更日志文件:经聊天的写入有凭据卡片;恢复靠备份——沿用既有的"不做产品内撤销"决定([系统总览](../system-overview.zh.md))。

## 永远不存的

- **凭证**——密码、验证码、支付信息。拒记并说明原因:记忆会随每次 agent 运行发给模型服务商,所以绝不能装秘密。
- **未经确认的推断。**
- **没有期限的临时状态**——agent 先问"记到什么时候?"。
- **属于业务域的东西**——截止日期、待办、账目。
- **敏感的自述**只照原话存,绝不改写成标签。

## 用户始终说了算

- **看**到真实条目——页面显示的就是文件(类别、日期、有效期),不是概括;问"你记得我什么"也逐条照原文列出。
- **改**只需一句话,两种语义分开处理:"现在变了"(替换,刷新日期)与"从来不对"(删除)。指代不清就问,绝不猜。
- 每次改动都**留痕**:经聊天的写入有凭据卡片,修改显示前后对比。没有产品内撤销;恢复靠备份。
- **不想被记**就什么都不用说:没人要求,就不会存。

## 机制

- 一个文件,三个固定小节,4000 字符上限。写满即拒,并问该忘掉什么——刻意逼出取舍,绝不静默摘要。
- 每一次写入——提取 agent 的,或手动保存的——都过同一套确定性校验,再原子替换文件。一次写入,要么全成要么全不成,与其他域一致。这是第一个非数据库存储:对"一域一库"([db-adapter](db-adapter.zh.md))的例外记录在此。
- 写入路径与记账同构:意图路由([chat-domain-capabilities](chat-domain-capabilities.zh.md))→ 结构化草稿(类别、内容、有效期——或要忘掉的条目)→ 校验 → 一次原子替换 → 凭据卡片。
- 读取路径:组合根把各域需要的类别交给它;运行时把它们渲染成该域 agent 提示词里的 `<memory>` 段([ai-pi-runtime](ai-pi-runtime.zh.md));意图分类器只看到约定。文件读不出来时,agent 降级为"无记忆"——记忆出故障绝不拖垮任何域——而记忆页如实报错。

## 刻意不进第一版的

- **无人确认的自动写入**——注意到的规律只提议,不入库。
- **复核提醒**——日后自然归问候域。
- **检索 / 语义搜索。**
- **按受众隔离**——单用户、单受众;Toby 哪天要替用户写给第三方时再重开。

## 九问自检

文章的验收测试,逐条给出 Toby 的答案:

| #   | 问题                                | Toby 的答案                                                           |
| --- | ----------------------------------- | --------------------------------------------------------------------- |
| 1   | 看到真实条目,而不是模型概括?        | 能——页面和"你记得我什么"都逐条照原文显示                              |
| 2   | 来源与最近确认时间?                 | 来源恒为用户明确说过的话;每条带最近确认日期                           |
| 3   | 能标临时、设到期、限范围?           | 到期可以(至某日);范围按类别,不逐条设置                                |
| 4   | 纠正后旧版本即失效?                 | 替换,绝不同时生效                                                     |
| 5   | 删除时连来源一起删?                 | 条目删除;聊天记录保留(历史是独立的、可见的一层)——此外没有别的存储     |
| 6   | 能让某段对话从不进入记忆?           | 天然如此——没人要求就不存                                              |
| 7   | 工作/家庭/人物的语境隔离?           | 人物按主体单独成类;各域可见性按类别;暂无其他语境                      |
| 8   | 能解释某条记忆何时影响了回答或行动? | 部分——凭据显示落了什么;监控面板显示每次运行的完整提示词,含 `<memory>` |
| 9   | 执行动作仍需权限?                   | 记忆从不发起或授权写入;约定只影响用户刚说的这句话的草稿               |

## 测试

与其他部分同一待遇:临时数据目录、脚本化的 AI——不碰真实模型,不碰生产 `data/`。真实模型的端到端试用(记住 → 用上 → 纠正 → 忘掉)是需要显式授权的手工步骤,结果单独汇报。
