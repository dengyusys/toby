# 为什么服务端选这套技术栈

[English](server-stack.md) | 简体中文

## 核心思路

选型只有一个标准:**自托管、单用户、单进程的个人项目,一切为简单和可控让路。**

能少一个进程,就少一个进程;能少一层框架,就少一层框架。

## Fastify

HTTP 框架选 Fastify:**小、快,插件模型直观。**

- 日常要用的东西内置了:JSON 解析、schema 校验、错误处理、路由组织,不用自己一块块拼
- 静态文件、cookie 这类能力以插件按需挂载,核心保持干净
- 不选 Express——太裸,错误处理和校验都要自己组装
- 不选 NestJS——个人项目不需要 IoC 容器和装饰器那套仪式感(2026-10 复议:已规划后续阶段迁移 NestJS;届时以新 ADR 取代本条)

## 数据库:SQLite + better-sqlite3,外加一个 MySQL 适配器

数据库是 SQLite——整个技术栈里最划算的一项——经[适配 port](db-adapter.zh.md)访问。同一个 port 还带一个 MySQL 适配器——出于学习目的而加,缘由见本节最后一段。

**一个文件就是一个库。**

- 没有数据库服务:没有端口、没有连接配置、没有开机自启、没有版本升级,少一个会坏的东西
- 备份就是复制文件:`data/` 目录整体拷走就是完整备份,校验和、打包、搬家全是文件操作
- 数据跟着项目走:清空 `data/` 就是干净重来,不在系统里残留任何服务

**同步 API,事务就是函数调用。**

better-sqlite3 是同步调用:没有连接池、没有断线重连、没有异步竞态。一个事务,就是用 begin / commit 包住一段普通代码。这对"提案确认后一次事务写入"的模型特别契合:重读目标、检查冲突、执行写入,整段原子,可推理。[数据库 port](db-adapter.zh.md)在这个驱动前面加了一层异步优先的面孔,但靠串行化所有操作保住了同样的保证。

**众所周知的短板,在这个项目里不存在。**

SQLite 的短板是单写者、不适合高并发。而 Toby 本来就只有一个写者(server 单进程),写入又全部走提案确认——低频、事务化,天生就是 SQLite 最舒服的场景。读多写少,WAL 模式下读写互不阻塞;单用户的数据量,连它能力的零头都用不到。SQLite 也是测试最充分的软件之一,可靠性不用怀疑。

**为什么不选 MySQL / PostgreSQL——以及为什么还是加了一个 MySQL 适配器。**

它们要多跑一个守护进程:端口、凭据、连接池、备份工具、升级,运维面直接翻倍;数据库密码又多一份要保管的敏感信息。这些代价换来的能力——高并发、多应用共享、海量数据——本项目一项都用不到。哪天真出现多进程写入或数据量问题再迁移不迟:数据就在文件里,迁移路径是清晰的。

尽管如此,适配 port 还是带上了一个 MySQL 适配器——作者出于学习目的加的:看看另一种方言接在同一个接口后面是什么体验,SQL 哪里可移植、哪里不可移植、连接池会改变什么。哪天第三种数据库想加入,也只是再多写一个适配器的事。推荐使用的仍然是 SQLite;MySQL 用来实验,不是必需。domain 代码看不到差别:驱动、连接池、方言细节全部止步于 port。

## typebox

**一个 schema 库,一份定义。**(早先这一节写的是 zod——但 zod 从未真正
安装过,校验一直由手写代码承担;typebox 把这个承诺落实,并随 AI 运行时
一并选定,见 [ai-pi-runtime.zh.md](ai-pi-runtime.zh.md)。)

- 外来的数据(AI 输出、HTTP 请求体、环境变量)过完校验才可信;schema 只
  定义一次、两处共用——ledger 的草稿 schema 既是面向模型的工具合同,
  也是服务端的形状闸门,两处永不漂移
- TypeBox schema 本身就是 JSON Schema:面向模型的合同与运行时校验出自
  同一份定义,校验侧用 `typebox/value` 的 `Check`/`Errors`
- 校验失败的信息足够定位到字段,不用猜哪里错了;同一份错误信息还能作为
  工具错误回喂给模型自行修正

## pino

**结构化日志:快,输出 JSON,够用。**

- 每条日志是带字段的对象,排查时按字段过滤,不用正则去啃文本
- 开销低,不拖请求
- 日志是给自己看的:不引入更重的可观测性套件,一个 pino 到头

## 本仓库的约定

- 生产是单进程:server 同时提供 API 与两个前端页面
- 外来数据(AI 输出、HTTP 请求体)先过 schema 校验(AI 链路用 typebox),再进业务逻辑
