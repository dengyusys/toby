# 手账域（Notes）

[English](notes.md) | 简体中文

> 目标契约(域未实施):职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

随口说的想法、决心、备忘,经提案确认写成 `data/notes/` 下的 Markdown 字条——「翻看记事本」的体验,任何编辑器可打开。

- **双轨存储**:月度流水(`YYYY-MM.md`,日小节 + 段落块字条,系统写)与主题本(非月度命名的 `.md`,文件名即主题,主人手工维护,系统只做点名续写与开新本)。
- 一条字条 = 一段主人原话;无标题行、无类型词、无分类。
- **不管**:主题本的改写/删除/合并(主人手编内容,AI 不乱动)、AI 自动按内容归类(点名才落)、目录索引视图、PC 端直接编辑(双端分工候选)。

## 核心概念

- 月度文件按月一文件,字条按日归入小节;主题本存量文件零迁移、天然被识别。
- 主题本标识 = 文件名,展示名 = 文件内首个 `# 标题`(缺失回落文件名)。
- 七种操作原语:月度新记/续写/改写/删除/合并 + 主题开新本/点名续写。

## 接口面

均为 JSON;错误包络沿用 server 惯例。

| 方法与路径                                    | 用途                                  |
| --------------------------------------------- | ------------------------------------- |
| `GET /api/notes/months`                       | 月度文件清单(降序)                    |
| `GET /api/notes?month=YYYY-MM`                | 月文件原文;不存在返回 `exists: false` |
| `GET /api/notes/topics`                       | 主题本清单                            |
| `GET /api/notes/topic?name=X`                 | 主题本原文(只交主题名,不交文件路径)   |
| `POST /api/notes/proposals`                   | 一句话生成字条提案(七原语之一)        |
| `POST /api/notes/proposals/:id/commit·cancel` | 确认 / 取消                           |

## 关键规则

- 锚定操作(续写/改写/删除/合并)以「最近字条 + 编号清单 + 正文摘录」指认目标;编号越界视为幻觉,降级为新记一条并留痕——错误合并比多一条字条伤害大。
- 改写/删除/合并生成时记录目标快照,commit 前重读文件比对,不一致整条作废——外部编辑以文件为准,server 绝不覆盖主人的手改。
- 新记与续写的正文永远用主人原话;改写由 AI 按指令生成完整替换正文,经「改前 → 改后」核对卡生效。
- 主题点名无失败路径:命中清单 → 续写既有本;没命中 → 开新本(提案卡明示「新开」);AI 给的名字不合法 → 降级月度新记并留痕。
- 新主题名的服务端校验(长度、路径分隔符、点开头、月度命名占用)同时是路径越界的唯一防线。
- 意图分界:写入手账内容 → 本域;查看/总结/回顾 → 书童只读工具应答。
- 提案 TTL 10 分钟;亮出 30 秒未取消由服务端自动写入,与人工确认同路径。
- 读面契约：月度文件不存在回 `exists: false` 不报 404；超长主题本截断并附标记。
