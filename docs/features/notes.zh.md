## 职责与边界

用户随口说的想法、决心、备忘，经提案确认写成 `data/notes/` 下的 Markdown 字条——「翻看记事本」的体验，文件任何编辑器可打开。

- **双轨存储**：月度流水（`YYYY-MM.md`，日小节 + 段落块字条，系统写）与主题本（非月度命名的 `.md`，文件名即主题，主人手工维护的文集，系统只做点名续写与开新本）。
- 一条字条 = 一段主人原话；无标题行、无类型词、无分类（2026-09-27 无标题化决策）。

**管**：`/api/notes*` 的只读面（月份清单、月文件原文、主题本清单与原文）与提案面（七操作原语的生成/确认/取消）；AI 判定（op 选择、主题点名）；书童只读工具（最近字条、主题本清单与全文）。

**不管**：主题本的改写/删除/合并（主人手编内容，AI 不乱动，留待单独决策）；AI 自动按内容归类主题（点名才落）；总结存回手账（总结是对话应答，走书童）；目录/索引视图；手账 PC 端直接编辑（双端分工方向候选）。

## 行为契约

### 存储

- `data/notes/` 只有 server 能写；月度文件按月一文件，字条按日归入小节。
- 主题本：非 `YYYY-MM.md` 的 `.md` 文件即主题本（点开头忽略）；文件名（去扩展名）即主题标识，文件内首个 `# 标题` 行为展示名（缺失回落文件名）；存量文件零迁移、天然被识别。
- 新主题名服务端校验：1–30 字符、禁路径分隔符与控制字符、禁 `YYYY-MM` 形态占用月度命名、禁点开头与 `..`——这道校验同时是路径越界的唯一防线（主题名直接拼进文件路径）。

### API

均为 JSON；启用认证时需会话 Cookie；错误包络 `{ error: { code, message } }`：

| 方法与路径 | 请求 | 成功响应 | 失败 |
| --- | --- | --- | --- |
| `GET /api/notes/months` | — | `200 { months: string[] }` 降序 | — |
| `GET /api/notes?month=YYYY-MM` | month 查询参数 | `200 { month, exists, markdown }`（月文件不存在时 `exists: false`、`markdown: ""`，不 404） | `400 INVALID_MONTH` 缺参 |
| `GET /api/notes/topics` | — | `200 { topics: [{ name, title }] }` 名称升序 | — |
| `GET /api/notes/topic?name=X` | name 查询参数（只交主题名，不交文件路径——服务端映射文件） | `200 { name, title, exists, markdown }`（不存在时 `exists: false`，不 404） | `400 INVALID_TOPIC_NAME` 缺参；名字非法 400 |
| `POST /api/notes/proposals` | `{ message, captured_at?, timezone? }`（键白名单，多余键 400） | `200` 字条提案（载荷见下） | `400 INVALID_REQUEST/INVALID_TEXT`；`400 TEXT_TOO_LONG`（message > 2000 字符）；AI 故障 `503 AI_*`、`504 AI_TIMEOUT`、`422` 输出非法 |
| `POST /api/notes/proposals/:id/commit` \| `/cancel` | 空请求体 | `200 { status, … }`（月度操作带落点月份；主题操作 `{ status, topic }`） | 生命周期内核与各域一致：`404` 不存在 / `410` 过期 / `409` 已取消或已提交幂等 |

提案载荷（对话域统一信封的 `proposal.payload`，不携带的操作字段为 null；月度五原语 + 主题两原语）：

- `entry`（`add` 新记，`{ date, body }`）、`append_to`（`append` 续写，目标为正文摘录指认）、`rewrite`（改写，旧值 → 新值对比）、`remove`（删一条）、`merge`（多条并成一条，最早一条承接、其余删除）；
- `new_topic`（`add_topic` 开新本，`{ name, body }`）、`topic_append`（`append_topic` 点名续写，`{ name, body }`）；
- 字段细节以 `apps/server/src/domains/notes/` 与根 HTTP 集成测试为准。

### 关键规则

- **操作原语注册表**：AI 能对手账做的事收敛为七种操作（月度 add/append/rewrite/remove/merge + 主题 append_topic/add_topic），操作目录（提示词片段）、校验映射、commit 分发三张表对齐在 `operations.ts`——新增操作 = 三表各加一项。
- **编号选认 + 确定性复核**：月度续写/改写/删除/合并的上下文为「最近 10 条（跨月）+ 编号清单 + 正文摘录」；AI 用编号指认目标，服务端校验编号落在清单内，越界视为幻觉——降级为新记一条并留痕（错误合并比多一条字条伤害大，整句被卡死才是新伤害）。
- **快照校验（锚定类操作）**：rewrite/remove/merge 在提案生成时记录目标条目快照，commit 前重读文件比对，不一致 `409 NOTE_CONFLICT`、提案作废重新生成——外部编辑以文件为准，server 绝不覆盖主人的手改；add/append 为纯追加，无冲突面。
- **原话纪律**：新记与续写的正文永远用主人原话；改写的正文由 AI 按主人指令生成替换后的完整正文，经核对卡（改前 → 改后）生效。
- **主题点名判定（无失败路径）**：命中清单（文件名或展示名精确匹配）→ 续写既有本；没命中 → 开新本（提案卡明示「新开」，错字由核对拦住）；AI 给的名字不合法 → 降级月度新记并留痕（消息内容不能丢）；想开的本已存在 → 落进它。commit 无 404/409 失败路径（外部删文件的极端时序除外）。
- **意图分界**：写入手账内容 → `notes`；查看/总结/回顾已有手账 → `none`（书童经 `get_recent_notes` 只读工具应答，跨月最近 20 条）；「记到 X 那本里」「开个新主题」→ `notes`。
- 提案 TTL 10 分钟，与各域一致；确认只交 URL 中的 `proposal_id`。提案亮出 30 秒未取消即由服务端自动写入（2026-10-05 用户决策），与人工确认同一条 commit 路径。

### 异常与边界

- `message` 空或非字符串 `400 INVALID_TEXT`；超过 2000 字符 `400 TEXT_TOO_LONG`。
- AI 判定输出非法（非 JSON/不合 op 枚举）经宽容提取与一次重试后仍失败才 `422`，对外错误语义与各域一致。
- 月文件或主题本不存在不 404——`exists: false` 由 Web 显示空态；书童读超长主题本时 6000 字符截断并附 `truncated` 标记，如实说明。
- 历史格式的旧条目（曾带标题行）原样保留、照常可被锚定操作指认。

## 安全边界

- 必须：所有写入走「生成提案 → 用户核对 → 用 URL 中的 `proposal_id` 确认」；确认可为发送下一条消息的隐式确认。
- 禁止：AI 或 Web 直接读写 `data/notes/` 文件；客户端提交文件路径（只交主题名）或超出契约的数据。
- 禁止：手账测试触碰真实 `data/notes/`——提案与存储测试必须使用临时数据目录。

## 验收

- 自动化（已通过，见 `apps/server/test/` 存储与提案服务单测、根 HTTP 集成测试、`apps/web/test/` 渲染测试）：七操作分发与越界降级、快照冲突拒绝、主题点名四形态、路径防呆（分隔符/`..`/超长/`YYYY-MM` 形态 400）、读面契约、Web 提案卡（含改写对比、开新本/续写）与「月份 | 主题」切换；全部使用临时数据目录、不调真实 AI。
- 真实数据只读冒烟（2026-10-05 已验，记录见 Git 历史）：十本主题本一次列出（中文名取自 `#` 标题）、`razors` 原文读回、月度面不回归、路径穿越 400。
- 真实 AI 盲测（同话题多次说并成一条、点名续写、开新本、改写对比）待用户复核。

## 开放问题

- 手账 PC 端直接编辑（双端分工方向首个候选，写入仍经 server 端点）。
- 主题本的改写/删除/合并（主人手编内容，日后单独决策）。

### 2026-09-27 · 手账操作框架（同日两次修订：remove/merge、无标题化）

**背景**：同一话题分多次说被记成多条字条——「续写」机制存在但链路几乎必然走新建（AI 只能看到最近 5 条的日期 + 标题、提示词偏向"拿不准一律 null"、续写目标要求标题逐字符相等）；用户指出本质是结构性问题——想改一条、总结一下、要个索引，每个诉求都要全链路加代码。
**取舍**：写侧收敛为**操作原语集 + 注册表驱动**（操作目录、校验映射、commit 分发三张表对齐，新增操作 = 三表各加一项，消除"每加一个功能全链路铺代码"）；**编号选认**替代标题照抄（回显数字比逐字符复制可靠；越界视为幻觉、降级新记留痕而非卡死）；`rewrite` 为该域首个非追加写操作，带**快照校验**——手账的卖点是"任何编辑器可打开、主人可手改"，server 能改写就必须承诺不覆盖手改，生成时快照、确认时比对是提案制下成本最低的乐观锁；总结走书童只读工具而非写路径（总结的消费方式是对话应答，落盘摘要会过期、与"文件即真相"相悖）。同日修订一：补齐 `remove`/`merge`（「手账不清理」修订为「删除可由 AI 提案、经核对」，跨月操作先校验全部再写）；同日修订二（无标题化）：字条只留原话段落块，标题行与类型词退役、分类整体取消，目标指认统一为正文摘录。

### 2026-10-05 · 手账双轨存储（月度流水 + 主题本）

**背景**：`data/notes/` 实际存在两类文件——系统写的月度流水与主人手工放入的十本主题文件（razors、芒格思维等 `# 标题` + 小节 + 表格的自由结构），后者对系统完全不可见（清单只认月份命名、Web 看不到、书童不知道存在）；用户要求手账支持按日期与按主题两种文件名。
**取舍**：非月度命名的 `.md` 即主题本——文件名即主题、首个 `#` 为展示名，存量十本零迁移；写入深度取「点名续写 + 开新主题」——主题本是主人手工维护的文集，不做条目级改写/删除/合并（风险大）；落点**点名才落**、AI 不自动按内容归类（易误归类，错落比不落更硌手）；主题名校验同时是路径越界的唯一防线；点名判定收敛到无失败路径（命中续写/没命中开新/名字非法降级月度留痕/已存在落进它）；书童加两个只读工具（列主题清单、读一本全文，6000 字符截断如实标记）。
