# 记忆域（Memory）

[English](memory.md) | 简体中文

> 现行契约:一条记忆是什么、记忆如何进入提示词、每次变化如何落地、记忆页长什么样。实现细节以代码与测试为准;完整设计理由见
> [personal-agent-memory](../decisions/personal-agent-memory.zh.md)。

## 这是什么

管家的活记忆:不等你吩咐就会学(静默学习),失效了就会忘,每次变化都向你播报。整个域由一条原则统摄——AI 有权记、有权忘,但每次变化都留回执,用户随时可以用一句话否决任何一条。存储是一个格式严格的 Markdown 文件,躲在仓库(repository)端口后面。

## 职责与边界

- 拥有 `data/memory/MEMORY.md`——全库唯一的非数据库存储(一域一库的记录在案例外),躲在记忆仓库端口后面;今天唯一的实现就是这个 Markdown 文件,将来可在组合根替换,域代码零改动。
- 拥有记忆工具(`recall` / `remember` / `forget` / `off_record`)、`<memory>` 提示词段的构建、不记忆会话开关,以及记忆页的 API。
- **不管**:事件(事件归 notes 和聊天历史;记忆只存没有域认领的稳定背景)、检索基础设施(没有向量——模型自己是检索器,工具只是翻本子)、记忆文件之外的任何写入。

## 核心概念

- 条目:三种类别,一条一行——刻意没有 id、没有来源、没有时间戳。

```markdown
## 约定

- 咖啡记「饮品」
- 出差期间餐饮记「差旅」 (至 2026-11-30)

## 关于我

- 不吃香菜

## 人物

- 小王:房东
```

- 一条记忆 = 类别 + 正文(人物另有 `name`)+ 可选的 `(至 YYYY-MM-DD)` 到期标记——必须是真实日历日期。`until < 今天`(UTC)即过期。
- 谁能看到:约定进每个会写库的 agent 和意图分类器(漏一条约定就是一笔静默的错账);关于我只影响聊天回答;人物帮聊天和记账认人(按人名命中——绝不自行给出金额或日期)。
- 解析器是确定性的,属于验证的一部分:解析不了的行拒绝整个写入;文件损坏在任何地方都被拒绝(`500 MEMORY_FILE_INVALID`,请手工修)——绝不静默修复。欢迎手工编辑该文件。
- 一次落地的变化的回执:`{action, type, before?, after?, created_at}`——before/after 引用渲染后的文件原文。卡片复用聊天的 proposal card;两个 web 按 `memory` 域 id 渲染。

## 怎么读

按遗忘的代价分级:

| 层                   | 机制                                                     |
| -------------------- | -------------------------------------------------------- |
| 约定                 | 全文写进每个会写库的 agent 与意图分类器的 `<memory>` 段  |
| 人物,写库时          | 在句子里按已记人名字面查找,命中的条目直接带上            |
| 人物 + 关于我,聊天中 | 目录(人名;关于我的正文)留在提示词里,详情用 `recall` 现查 |

- `<memory>` 段每次运行现取现算,渲染在 `<rules>` 之后、`<context>` 之前;它是唯一允许点名的段落(记忆索引的标题刻意写着 `recall` 工具)。
- `recall` 笨到底:名字与正文的子串匹配、不区分大小写、全类别、只查未过期;不给 keyword 就翻整本——「你记得我什么」就这样逐条原文作答。换说法是模型的事。
- 文件损坏时段落降级为一条可见占位（记忆文件当前无法读取）——聊天继续能用,记忆 visibly 坏着。

## 怎么写

- 三个会话工具:`recall`(read-only)加 `remember` / `forget`(write-intent)。会话型 agent(聊天的 none 智能体、记账的提取智能体)一律全带——静默学习搭上当时正在跑的任何一个 agent。`off_record`(write-intent)为显式的「这通别记 / 可以记了」句子存在,只挂在记忆域自己的 agent 上。
- 显式的记忆句子(记住X / 忘掉X / 你记得我什么 / 这通别记)像任何已注册域一样路由到记忆能力;记忆 agent 用同一组工具解析它们。
- 定位旧行:改与删各带一个关键词,用与 recall 完全相同的子串规则在名字与正文、未过期条目里找。恰好一条 → 替换或删除;多条 → 拒绝并逐条列出候选(解不开就问,绝不猜);零条 → forget 回「没有相关记忆」,带替换的 remember 视为新增追加。纯追加先查重(完全相同 → 已记得)。
- 每次写入:确定性验证(格式、真实日历日期、替换还是去重、上限)→ 一次全文原子替换(临时文件 + rename)→ 回执。页面的编辑/删除用同一纪律,定位方式是整行精确匹配。
- 上限 500 条:满了就是拒绝加一句「该忘点什么？」——绝不静默截断,绝不自动摘要。
- 不记忆:一句话或页面开关给当前对话立旗;旗开着,一切 `remember` / `forget` 调用在工具处被拒(拒绝对模型与 traces 可见),新对话开始时自动复位。删除就是删除,不是封禁——重学的条目留下新的回执。
- 在聊天里,运行中途落地的 remember/forget 会在 transcript 之后各自成一张卡片(静默学习保持可见);记账写入的响应可能携带可选的 `memory_receipts` 附带——没学到东西就不带。

## 记忆页

管家的备忘录,不是数据库表格——两个 web 按约定 → 关于我 → 人物分组渲染;过期条目排在最后,等续期或删除;每条可就地编辑、删除;顶栏按需导出 `.md` 快照(服务端不落盘);不记忆开关也在这里。

## 接口面

除导出(`text/markdown`)外全部 JSON;每条路由都走会话守卫;错误沿用 server 唯一的错误体。

| 方法与路径                       | 用途                                               |
| -------------------------------- | -------------------------------------------------- |
| `GET /api/memory`                | 全部条目,约定 → 关于我 → 人物,到期已判定           |
| `POST /api/memory/entries`       | 追加(或带 replaceKeyword 替换)一条 → 回执          |
| `POST /api/memory/entry/replace` | 整行精确匹配的替换或删除(`current`,`next \| null`) |
| `POST /api/memory/entry/forget`  | 删除唯一的关键词命中 → 回执                        |
| `GET /api/memory/export`         | `.md` 快照,仅按需                                  |
| `GET /api/memory/off-record`     | 不记忆开关状态                                     |
| `POST /api/memory/off-record`    | 设置开关                                           |

| 失败               | 答复                                    |
| ------------------ | --------------------------------------- |
| 形状或取值违反格式 | `400 INVALID_ENTRY`                     |
| 没有匹配的条目     | `404 ENTRY_NOT_FOUND`                   |
| 多条命中 / 重复行  | `409 AMBIGUOUS_ENTRY`(message 里列候选) |
| 完全相同的行已存在 | `409 DUPLICATE_ENTRY`                   |
| 到达上限           | `409 LIMIT_REACHED`(该忘点什么？)       |
| MEMORY.md 解析不了 | `500 MEMORY_FILE_INVALID`(请手工修)     |

## 不变式

1. 一次写入 = 一次验证过的全文原子替换;没有部分写入,也没有第二份存储(没有常驻同步的导出文件)。
2. 解析器属于验证;解析不了的一律拒绝,绝不修复。
3. 每次落地的变化都留下引用文件原文的回执;替换绝不与旧行并存。
4. 过期条目只出现在页面最后一组——不进提示词、不被 recall、不参与查找。
5. `remember` / `forget` 与页面的整行端点是仅有的写路径;旗开着时工具一律拒绝。
6. AI 永远看不到文件路径;工具边界就是全部界面。

## 暂不在契约内

- 向量、embedding 或任何检索基础设施——模型自己是检索器。
- 否决清单或按主题的屏蔽:删除就是删除;重学靠可见性(回执)加一句话再删来应对,不靠预防。
- 按条目的范围或来源;数据库适配器(端口留着门)。
