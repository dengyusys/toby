# 记账域（Ledger）

[English](ledger.md) | 简体中文

> 职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

- 记账:对话页一句话(可含多笔)生成提案,核对确认后写入记账数据库(SQLite 方言为 `data/ledger.db`,MySQL 方言为 `toby_ledger` schema)。
- 查看:按月看每日收支小计与月度汇总、分类合计。
- 删除:用户主动发起、界面显式确认后删除单笔已落库交易——全域唯一不走提案管线的写入。
- 金额全程以**整数分**存储,不引入浮点误差。
- **不管**:记录的修改、预算与报表图表、多账户体系、多币种。

## 核心概念

- 一笔交易 = 日期 + 类型(收/支)+ 分类 + 账户 + 金额(分)+ 备注;账户可省略,缺省记为「未关联」。
- 一句话里的多笔全部提取:一张提案携带 1–10 笔,确认一次、整批原子写入。

## 接口面

均为 JSON;错误沿用 server 唯一的错误体。**请求形状**违规(没有 intake 路径、`text` 不是字符串、条目类型不认识)由路由 schema 答 `BAD_REQUEST`;形状合法但取值荒唐(金额不合法、日期不存在、分类为空白)由域答 `INVALID_ENTRY`。

| 方法与路径                                   | 用途                                                               |
| -------------------------------------------- | ------------------------------------------------------------------ |
| `GET /api/ledger/months`                     | 有记录的月份列表(降序)                                             |
| `GET /api/ledger/transactions?month=YYYY-MM` | 月度交易 + 汇总(收支合计、分类合计)                                |
| `POST /api/ledger/proposals`                 | 一句话(AI,可多笔)或结构化单笔(确定性路径)生成提案;不确定则返回追问 |
| `POST /api/ledger/proposals/:id/commit`      | 确认:整批原子落库(幂等)                                            |
| `POST /api/ledger/proposals/:id/cancel`      | 取消提案                                                           |
| `DELETE /api/ledger/transactions/:id`        | 删除单笔交易(用户主动发起;id 不存在答 404 `TRANSACTION_NOT_FOUND`) |

## 关键规则

- AI 提取结果视为不可信输入,必须过域内确定性校验与归一化后才生成提案。
- 金额:最多两位小数的非负数,拆位解析为分;日期:本地格式 + 日历校验,任意过去或未来日期合法(补记账);未提及日期默认今天。
- 字段不确定时返回追问,不猜;用户补充后重试。
- 提案 TTL 10 分钟;亮出 30 秒未取消由服务端自动写入;commit 幂等,不产生重复行;已取消的提案拒绝提交,过期提案返回 410;过期 1 小时后记录被清理,此后返回 404。
- 任一笔失败整批回滚。
- 删除按 id 单行事务执行;id 必须是正整数(否则 `INVALID_ENTRY`),不存在的 id 答 404 `TRANSACTION_NOT_FOUND`(重复删除即此路径)。
