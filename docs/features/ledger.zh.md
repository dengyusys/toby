# 记账域（Ledger）

[English](ledger.md) | 简体中文

> 职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

- 记账:对话页一句话(可含多笔)即成直接写入——整批以一个事务立即落库,卡为凭据(SQLite 方言为 `data/ledger.db`,MySQL 方言为 `toby_ledger` schema)。
- 查看:按月看每日收支小计与月度汇总、分类合计。
- 删除:用户主动发起删除单笔已落库交易。
- 修改:对单笔已落库交易的部分事务性更新——结构化 PATCH 路径,或由匹配条件确定性解析的 AI 纠错(「把昨天午饭那笔改成 35」)。
- 金额全程以**整数分**存储,不引入浮点误差。
- **不管**:预算与报表图表、账户体系、多币种。

## 核心概念

- 一笔交易 = 日期 + 类型(收/支)+ 分类 + 金额(分)+ 备注。
- 一句话里的多笔全部提取:一条指令携带 1–10 笔,整批原子写入——一张凭据卡。
- 一次修改 = 匹配条件 + 部分补丁:传了的字段才变,未传字段保持原样。AI 永远不给行 id——由服务端按某一天的行(指定日,否则今天)解析条件;恰好一个候选即落库,零个或多个则返回追问。

## 接口面

均为 JSON;错误沿用 server 唯一的错误体。**请求形状**违规(没有 intake 路径、`text` 不是字符串、条目类型不认识)由路由 schema 答 `BAD_REQUEST`;形状合法但取值荒唐(金额不合法、日期不存在、分类为空白)由域答 `INVALID_ENTRY`。

| 方法与路径                                   | 用途                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `GET /api/ledger/months`                     | 有记录的月份列表(降序)                                                                                              |
| `GET /api/ledger/transactions?month=YYYY-MM` | 月度交易 + 汇总(收支合计、分类合计)                                                                                 |
| `POST /api/ledger/entries`                   | 一句话(AI,可多笔)或结构化单笔(确定性路径)直接写入;不确定则返回追问                                                  |
| `PATCH /api/ledger/transactions/:id`         | 部分更新一笔交易:传了的字段才变,未传字段保持原样(空补丁答 `INVALID_ENTRY`;未知 id 404)。AI 纠错路径落在同一条写入上 |
| `DELETE /api/ledger/transactions/:id`        | 删除单笔交易(用户主动发起;id 不存在答 404 `TRANSACTION_NOT_FOUND`)                                                  |

## 关键规则

- AI 提取结果视为不可信输入,必须过域内确定性校验与归一化后才会发生任何写入。
- 金额:最多两位小数的非负数,拆位解析为分;日期:本地格式 + 日历校验,任意过去或未来日期合法(补记账);未提及日期默认今天。
- 字段不确定时返回追问,不猜;用户补充后重试。
- 写入路径:直接写入——整批一次事务立即落库;卡是凭据。没有撤回端点,没有确认门;写错了再写一次或靠备份恢复。
- 任一笔失败整批回滚。
- 修改遵循同一条「先校验、后一次事务」的纪律:补丁逐字段按新记一笔的规则校验(备注传空串即清空),读行与更新在同一事务内,结果携带该事务内的前/后值。
- AI 纠错:模型提交匹配条件加补丁——从不提供行 id。服务端确定性解析候选;恰好一个落库,零个或多个变成一句追问(点名日期,最多列五个候选)。纠错绝不会多记一笔重复账。
- 删除按 id 单行事务执行;id 必须是正整数(否则 `INVALID_ENTRY`),不存在的 id 答 404 `TRANSACTION_NOT_FOUND`(重复删除即此路径)。
- 提取智能体是会话型的:携带三个记忆工具和 `<memory>` 段(约定全文,外加句子里命中的已记人名的 人物 条目);提取中途落地的 remember/forget 以可选的 `memory_receipts` 附带随写入响应返回——没学到东西就不带(见 docs/features/memory.zh.md)。
