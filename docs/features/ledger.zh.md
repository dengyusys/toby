# 记账域（Ledger）

[English](ledger.md) | 简体中文

> 目标契约(域未实施):职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

- 记账:对话页一句话(可含多笔)生成提案,核对确认后写入 `data/ledger.db`。
- 查看:按月看每日收支小计与月度汇总、分类合计。
- 金额全程以**整数分**存储,不引入浮点误差。
- **不管**:记录的修改与删除、预算与报表图表、多账户体系、多币种。

## 核心概念

- 一笔交易 = 日期 + 类型(收/支)+ 分类 + 账户 + 金额(分)+ 备注。
- 一句话里的多笔全部提取:一张提案携带 1–10 笔,确认一次、整批原子写入。

## 接口面

均为 JSON;错误包络沿用 server 惯例。

| 方法与路径                                   | 用途                                                               |
| -------------------------------------------- | ------------------------------------------------------------------ |
| `GET /api/ledger/months`                     | 有记录的月份列表(降序)                                             |
| `GET /api/ledger/transactions?month=YYYY-MM` | 月度交易 + 汇总(收支合计、分类合计)                                |
| `POST /api/ledger/proposals`                 | 一句话(AI,可多笔)或结构化单笔(确定性路径)生成提案;不确定则返回追问 |
| `POST /api/ledger/proposals/:id/commit`      | 确认:整批原子落库(幂等)                                            |
| `POST /api/ledger/proposals/:id/cancel`      | 取消提案                                                           |

## 关键规则

- AI 提取结果视为不可信输入,必须过域内确定性校验与归一化后才生成提案。
- 金额:最多两位小数的非负数,拆位解析为分;日期:本地格式 + 日历校验,任意过去或未来日期合法(补记账)。
- 字段不确定时返回追问,不猜;用户补充后重试。
- 结构化单笔是同一提案端点的确定性路径,供测试与程序化调用。
- 提案 TTL 10 分钟;亮出 30 秒未取消由服务端自动写入;commit 幂等,不产生重复行。
- 任一笔失败整批回滚;确认后面板重新拉取,与日程刷新同节奏。

## 验收要点

- 校验归一化:坏金额、坏日期拒绝且零写入零提案;AI 坏输出同样被拦(stub 测试锚定)。
- 提案生命周期四态:commit 落库、幂等、取消拒提交、过期 410。
- 多笔整批原子性;空库空态;HTTP 契约全端点。
