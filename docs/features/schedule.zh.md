# 日程域（Schedule）

[English](schedule.md) | 简体中文

> 目标契约(域未实施):职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

自然语言进对话,变成受限、可验证的日程修改提案;字段级展示旧值与新值;确认后才写入(显式确认 / 下一条消息默许 / 亮出 30 秒到点,三者任一)。

- 日程内容由**记录项(tracker)**承载:系统不预装、无内置分类,要记什么由用户经对话创建(提案制);定义即数据,新增与调整字段不需要改代码。
- **管**:记录项定义的创建/归档/字段调整(提案制)、只读查询、提案生成与确认、AI 解析与校验、冲突检测与事务。
- **不管**:频率与期限规则引擎、跨项统计(归书童智能体)、改 slug/改字段类型/删字段/删历史数据、离线队列与撤销。

## 核心概念

- 记录项 = slug + 名称 + 字段(布尔/数值/单选枚举/文本/时间五种);同时活跃的记录项有上限。
- 月份自记录派生:无记录的月份不存在,首笔写入即建月。
- 否定语义只置布尔 `false`:解析是无状态的,旧明细不被指令自动清理。

## 接口面

均为 JSON;错误包络沿用 server 惯例。

| 方法与路径                                | 用途                               |
| ----------------------------------------- | ---------------------------------- |
| `GET /api/schedule/months`                | 有记录的月份列表                   |
| `GET /api/schedule/trackers`              | 记录项定义(含已归档)               |
| `GET /api/schedule/records?month=YYYY-MM` | 月份记录(记录项原生形状)           |
| `POST /api/schedule/commands/text`        | 一句话生成提案(限流与对话域同窗口) |
| `POST /api/schedule/proposals/:id/commit` | 确认写入(幂等)                     |
| `POST /api/schedule/proposals/:id/cancel` | 取消提案                           |

## 关键规则

- AI 只收到指令文字、采集时间、时区和按活跃记录项动态生成的 schema;不接收日程内容、路径、密钥或工具。
- 输出过 schema/日期/记录项/字段/枚举校验才成提案;未定义字段与枚举外值确定性拒绝并转追问。
- 记录项调整只允许加字段与停用字段,至少保留一个未停用;停用是定义标记,历史数据原样保留。
- 读取宽容、写入严格:历史未登记枚举值照常展示,写入一律过当前定义。
- commit 在事务内重读目标字段、与提案期望比对,经串行队列写入;不一致整条拒绝,零变更。
- 提案动作四类:字段写入、建记录项、归档记录项、调整记录项;TTL 10 分钟,亮出 30 秒未取消由服务端自动写入(同一条 commit 路径)。

## 验收要点

- 四态零写入:未确认、取消、过期、歧义追问都不改数据;重复确认幂等;字段冲突整条拒绝;无关字段保留。
- 空库起步全程自然语言:建项(含枚举字段)→连续记录→归档,无代码改动;AI 产出被定义约束。
- 真实 AI 调用走手动验证,不属于自动化测试。
