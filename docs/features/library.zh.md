# 书库域（Library）

[English](library.md) | 简体中文

> 目标契约(域未实施):职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

PC 端书库页上传一本小说,server 拆成章节,生成「导入《书名》共 N 章」提案卡;确认后整书落入 `data/library/`,之后可浏览书单与章节正文。这是小说助眠规划的第二期(文档内核 → **书库** → 助眠改写 → 语音)。

- 上传只产生提案,不落盘;确认前一个字节不进 `data/library/`。
- 拆章在本地 Python 子进程完成:识别不到章节结构时整书作单章「全文」——导入永远可行,切分质量在提案卡与章节目录里如实可见。
- 移动端本期不设入口(上传导入属复杂操作,归 PC)。
- **不管**:删书改书、助眠改写(第三期)、语音(第四期);对话意图路由不接入书库(导入是文件上传流程,不是一句话事务)。

## 核心概念

- 一本书一个目录:`manifest.json`(书目与章节清单)+ 各章 Markdown,自含可读。
- 导入原子性:先写 staging 目录全量内容再改名落位,中断不留半本书;manifest 是唯一有效性依据。
- 书 id 有严格格式,路径拼接前校验,不吃路径穿越。

## 接口面

上传为 multipart(「只收 JSON」的破例端点之一);其余 JSON;错误体沿用 server 惯例。

| 方法与路径                                   | 用途                                    |
| -------------------------------------------- | --------------------------------------- |
| `POST /api/library/books`                    | 上传单文件拆章,返回导入提案(含预览章名) |
| `POST /api/library/proposals/:id/commit`     | 确认:整书落盘(幂等)                     |
| `POST /api/library/proposals/:id/cancel`     | 取消:不落盘                             |
| `GET /api/library/books`                     | 书单                                    |
| `GET /api/library/books/:id`                 | 书目 + 章节目录                         |
| `GET /api/library/books/:id/chapters/:index` | 章节正文                                |

## 关键规则

- 拆章子进程只收临时文件路径:数组参数、无 shell、只读、无网络。
- 本域不向 AI 供应商发送任何内容;书库数据不出本地。
- 书名优先级:epub 内置标题 → 上传文件名去扩展名。
- 白名单外格式 415、超限 413、无法解析的文件(无文本层/损坏/DRM/解释器缺失)422——绝不半截落盘。
- 提案生命周期与各写入域同款(TTL 10 分钟、30 秒自动写入、取消是唯一拒绝方式);确认只交 `proposal_id`。
