# 告示板域（Todo）

[English](todo.md) | 简体中文

> 目标契约(域未实施):职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

一句话进对话、提案卡确认后写入待办数据库（SQLite 方言为 `data/todo.db`，MySQL 方言为 `toby_todo` schema）的一次性待办告示板。

- **管**：新办（一句话单条或多条）、勾销（办完了）、撕掉（不要了）、按截止回看。
- **不管**：周期性事务（归日程）、长期偏好（归记忆）、想法与心情（归手账）；改期、优先级、子任务、勾销后重开。

## 核心概念

- 一条待办 = 标题（≤20 字行动短语）+ 备注（用户原话）+ 截止日期/钟点（可空，即未定期）+ 状态 `open`/`done`。
- 一句话说了几件事，逐件拆成多条，进同一张提案卡；不并成一条标题。
- 只有 server 写库；书童智能体可经只读工具查板。

## 接口面

均为 JSON；错误包络沿用 server 惯例。响应形状与错误码以落地时的代码与测试为准。

| 方法与路径                             | 用途                                                                                |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| `GET /api/todos`                       | 全量列表，按截止排序，未定期排后                                                    |
| `POST /api/todos/proposals`            | 一句话生成提案：新办 / 勾销 / 撕掉 / 全部勾销；指认不出目标或不是要办的事则返回追问 |
| `POST /api/todos/proposals/:id/commit` | 确认写入（幂等）                                                                    |
| `POST /api/todos/proposals/:id/cancel` | 取消提案                                                                            |
| `POST /api/todos/complete`             | 面板直写：勾销所选（仅 PC 端）                                                      |
| `POST /api/todos/remove`               | 面板直写：撕掉所选（仅 PC 端）                                                      |

## 关键规则

- AI 只拟标题与截止；备注永远用用户原话，不改写。
- 勾销/撕掉的目标只能从服务端注入的未办清单里选，服务端二次校验。
- 说不出截止就是未定期，不猜不凑；有钟点必有日期。
- 多条写入走同一数据库事务，任一条非法整体回滚。
- 全部勾销以起草时点的快照为准，确认前新增的待办不被扫入。
- 提案 TTL 10 分钟；亮出 30 秒未取消由服务端自动写入，与人工确认同路径、幂等。
- 面板直写仅限 PC 端「显式勾选 + 确认框」，不经提案；移动端纯回看。
- 意图分界：「提醒我…」一次性 → 本域；「以后都…」→ 记忆；按日打卡 → 日程；想法心情 → 手账。

## 验收要点

- 提案流：生成不落库、确认幂等、取消后拒确认、过期 410。
- 直写：任一 id 未知整体回滚；撕掉不可恢复、勾销不可重开，确认框明示。
- 意图：新办 / 勾销 / 撕掉 / 追问四形态全覆盖，含一句话多件事拆条。
- Web：多条提案卡、划线回看、批量模式交互。
