# 问候域（Greeting）

[English](greeting.md) | 简体中文

> 目标契约(域未实施):职责、接口与关键规则;实现细节以代码与测试为准。

## 职责与边界

用户每次打开或刷新网页,书童主动说一句问候(AI 生成、按时段固定文案兜底);问候只当次展示,不写入任何数据库。

- 同一条 SSE 长连接还承载对话处理阶段的进度播报:等待回复期间,等待状态行按实际阶段展示(「理解你的话」「核对日程」…)。
- **不管**:开场播报与待办提醒等其他推送(远期候选)、双向通信、问候持久化与历史回看、多用户在线状态。

## 核心概念

- SSE 事件流三种帧:问候帧(连接建立时,先于一切保活帧)、进度帧(对话处理推进到新阶段时广播,尽力而为)、注释保活帧(每 25 秒)。
- 进度短语由 server 在处理路径上确定性播报,不经 AI 生成;Web 收到即固定显示,通道不可用时回退本地兜底词,回复落定即清空。

## 接口面

| 方法与路径              | 用途                                             |
| ----------------------- | ------------------------------------------------ |
| `GET /api/greeting?tz=` | SSE 事件流;tz 为 IANA 时区,缺失或非法按 UTC 兜底 |

## 关键规则

- 问候**永不缺席**:未配置 AI、调用失败、超时或输出不合格时回退按时段固定文案;问候服务对外不抛错。
- 问候以「先生」称呼主人:AI 提示词与兜底文案同纪律。
- 去重窗口 30 秒(键为会话令牌摘要):挡断线重连与开发态双挂载的重复问候;窗口过期后新连接恢复问候。
- 问候**不入库**:Web 端以本地前缀 id 追加为 assistant 消息,刷新即逝,不进对话库,不参与意图路由。
- Web 在会话历史恢复完成后才连接问候通道,保证问候不被历史恢复覆盖;连接错误静默关闭,不自动重连。
- 进度播报广播给所有在线连接;无连接静默丢弃,推送失败不影响对话处理。

## 验收要点

- 问候服务:时段兜底、AI 输出清理、失败回退,永不抛错。
- 事件流契约:响应头、问候帧次序、去重窗口与过期恢复、401/405。
- 进度帧:各处理阶段的播报次序、断开静默;Web 端真实阶段固定显示与兜底轮换。
