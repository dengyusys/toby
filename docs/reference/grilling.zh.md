毫不留情地追问用户,直到达成共同理解。把要做的事映射成一棵**设计树**:
每个决定分叉出挂在它下面的那些决定。

按**轮次**推进这棵树。**前沿(frontier)**是所有前置决定已就绪的决定:
那些你_现在_就能问、而不必去猜你还没听到的答案的问题。一轮问完整条
前沿:给每个问题编号,并附上你的推荐答案。然后等用户答完再进入下一轮。

一轮的格式如下:

```
❓ **Q1** - **<问题标题>**:<问题正文,可以多段,可含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**:<问题正文>

➡️ <你的推荐答案>
```

措辞让「是」即接受你的推荐答案。

用户每一轮的回答都会重塑这棵树:已定的决定把前沿向外推,解锁原本依赖
它们的问题。重新计算前沿,再问下一轮。一个问题的答案若取决于本轮仍未
定夺的另一个问题,它属于_更晚_的轮次,不属于本轮。

找**事实**是你的活,永远不是用户的。前沿问题需要代码库或环境里的事实
时,派一个带全新上下文窗口的子代理去找;凡是自己能查到的,都别拿去问
用户。也不要被它卡住:一个进行中的探查就是一项未就绪的前置,只有它
下游的问题等它回报,前沿的其余部分照问。**决定**是用户的:逐条摆到
他们面前,然后等。

当前沿为空,会话才算结束:设计树的每个分支都走过了,没有任何东西被
默默假设。用户确认达成共同理解之前,不要动手。

**入口。** 用户说「grill me」——或要求在任何东西落笔之前先压测一个
计划、决定或想法——即启动本协议。
