name: writing-for-agents

description: 为 agent 编写文档。创建或编辑 skill、修改 AGENTS.md / CLAUDE.md 时使用。

写给 agent 消费的任何文档的参考:一个 skill、一份 `AGENTS.md` /
`CLAUDE.md`、一篇被指针指向的文档。封装不同,写法相同:同样的杠杆让每一
份都变得可预测,因为 agent 每次运行走的是同一个_过程_,而不是产出同一个
结果。

要写的文档是 skill 时,先读
[`SKILL-MECHANICS.md`](https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL-MECHANICS.md),了解 frontmatter、调用方式的选择与路由 skill。

## 上下文指针(context pointer)

**上下文指针**是 agent 上下文里持有的一条引用:它点名一份上下文之外的
材料,并编码了到达它的条件。skill 的 description 是一个;`AGENTS.md` 里
点名某文档的一行是同一个东西。决定 agent 何时触达材料、触达得多可靠
的,是指针的_措辞_,不是它的目标。一个必备的材料配上一条措辞无力的指
针,是一个方差 bug:先磨利措辞,磨利仍失败才把材料内联进来。

一个指针干两件事:说明材料是什么,并列出触发到达的**分支**(branch,指
文档处理的一个独立情形,不同运行会走不同路径)。常驻指针的每个词每一轮
都要付费,所以它比正文更该狠剪:

- **引导词前置**:指针正是靠开头完成触发工作的。
- **一个分支一个触发词。** 给同一个分支换名的同义词,是把一个分支写了
  两遍;合并它们,只留真正不同的分支。
- **正文已经承载的身份信息,删掉。**

## 两种负载(two loads)

你添加的每份文档、每个指针,都花两种预算之一:

- **上下文负载(context load)**:常驻材料在 agent 窗口上的开销——
  `AGENTS.md` 的一行、skill 的 description、任何每轮都坐在上下文里的东
  西,无论触不触发都在花 token 和注意力。
- **认知负载(cognitive load)**:人这边的开销——存在哪些文档、什么时
  候拿哪份。人就是索引。这不是要压到最低的成本:它是人类能动性的价
  格;在人类判断要紧的地方花它,在不要紧的地方省掉它。

只通过指针触达的材料免掉上下文负载,代价是指针自己那一行;完全没有指针
的材料则全程骑在认知负载上。

## 信息层级(information hierarchy)

文档由两类内容构成:**步骤**(steps,agent 依序执行的动作)和**参考**
(reference,按需查阅的定义、规则、事实)。两者可自由混排:全是步骤(一
份食谱)、全是参考(一套评审规则、本 skill)、或兼有。核心决策是每一块
内容坐在**信息层级**的哪一级——一架按"agent 需要它的紧迫程度"排序的
梯子:

1. **文件内步骤**是第一梯队:agent 要做的事,按顺序。
2. **文件内参考**按需查阅。常常是一个正当的平级集合(一套评审规则的
   每一条在同一级),这是好安排,不是坏味道。
3. **外置参考(disclosed reference)**被推到单独文件里,由上下文指针
   触达,指针触发时才加载。近可以是同目录的兄弟文件,远可以是住在任
   何地方、任何文档都能指的完全外部参考。

往下推得太少,顶部就会臃肿;推得太多,你会藏起 agent 真正需要的材料。
这个张力就是决策的全部。

**渐进披露(progressive disclosure)**就是沿梯子下移(移出主文件、放到
指针后面),让顶部保持可读。它主要不是 token 优化:它是保护层级的方
式。分支是最干净的披露检验:每个分支都需要的,内联;只有部分分支触达
的,放到指针后面。文档有步骤时,本该外置的文件内参考会把步骤埋掉,让
"注意到它们"变成掷硬币——这是个方差杠杆,不只是可读性杠杆。

**共置(co-location)**是文件内的同伴:层级梯子决定一块内容坐多低,共
置决定它旁边坐什么。把一个概念的定义、规则、注意事项放在同一个标题
下,别撒开,读一部分就把邻居带上。检验标准:文档应该读起来像"为 agent
写的文档"。成组的内容读起来像;撒开的不像。(与重复不同:重复是把同
一个意思在两处写两遍;撒开是把一个意思碎成许多片。)

**蔓延(sprawl)**是这里的失败模式:文档单纯地太长,哪怕每一行都有效
且唯一。注意力被摊薄,而每多一行就多一行要维持其相关性。解药是梯子:
把参考披露到指针后面,并按分支或顺序拆分,让每条路径只带它需要的。

## 步骤与完成判据(completion criteria)

每个步骤都要落在一个**完成判据**上——告诉 agent 活干完了的条件。两个
性质使它成为杠杆:

- **清晰**:agent 分得清"完了"和"没完"吗?模糊的边界("达成理解")会
  招来**过早完成**:活还没真干完就结束步骤,注意力滑向_完成感_。还看
  得见的后续步骤(**后续步骤**,post-completion steps)提供拉力,判据
  的清晰度提供阻力。按顺序防御:**先磨利边界**(局部且便宜);只有当
  它确实无法磨利_且_你观察到赶工,才靠拆分序列藏起后面的步骤。藏只跨
  真实的上下文边界才有效(一次交接或一次子 agent 派发;内联调用会把后
  续步骤留在上下文里,什么都清不掉)。
- **要求量**:它要多少。"每个改动的模型都有着落"逼出扎实的活,
  "产出一份变更清单"逼不出。要求量驱动**跑腿工作**(legwork,agent 在
  活儿内部做的挖掘,潜伏在措辞里而不是单列为一步),且不限于步骤:
  "每条规则都已应用"约束一整块平级参考,正如"每步都做完"约束一个序
  列——纯参考文档就是这样带上完备性门槛的。

最强的判据既可检验又完备。

## 何时拆分

把一份文档拆成两份要花掉两种负载之一,所以只在拆分真的划算时拆:

- **按顺序拆**:当后续步骤诱惑 agent 赶完眼前这步时,把一段步骤拆开。
  让后续步骤离开视野,能把更多跑腿工作逼到当前任务上。小心反面:合并序
  列会让每一步的后续步骤暴露给下文,招来过早完成。
- **按调用方式拆**,skill 专属:见
  [`SKILL-MECHANICS.md`](https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL-MECHANICS.md)。

## 引导词(leading words)

**引导词**是模型预训练里已有的紧凑概念,agent 跑文档时用它思考
(_lesson_、_fog of war_、_tracer bullets_)。作为 token 反复出现、绝不
展开成句子,它积累出一个分布式定义,用最少的 token 锚定一整片行为——
靠的是招募模型已有的先验。自己造词也行、只要定义清楚,但造的词召不来
先验:预训练的词白送,造的词要你花定义的 token 去买;先够已有的词。

它锚定两次。正文里锚定_执行_:这个词一出现,agent 就够向同一个行为;
在平级参考里,它把注意力聚焦到要找的那一类东西上。指针里锚定_调用_:
当同一个词活在你的提示词、文档和代码库里,agent 会把这门共同语言和材
料挂钩,更可靠地触达它。

猎取用引导词重构的机会。在三个地方全文拼写的三件套;花一整句去比划一
个想法的指针。每处都是一段乞求坍缩成单个 token 的文字:

- "快、确定、低开销" → _tight_(一个 _tight_ loop)。
- "一个你信得过的循环" → _red_,把一个模糊的门变成二元可观察状态(这
  个循环对这个 bug 变_红_,或者不变)。

你赢两次:token 更少,agent 挂靠思考的钩子更锋利。假设每份文档都背着
引导词能退役的同义反复,去找出来。

**否定式(negation)**是这个杠杆旁的失败模式:靠禁止来转向,会把被禁
的行为拖进上下文,让它_更_可得,而不是更不可得。*别想大象*,结果满脑
子都是大象;否定词是个弱修饰符,压不过强激活的概念,禁令一半读起来像
在做这件事的指令。用**正向**提示:陈述目标行为("写一行式注释"),让
被禁的那个根本不被说出。禁令只有在无法正向表述的硬护栏场景才配存在;
即便那时,也要配上正向目标,让注意力落在要做什么上。

## 修剪(pruning)

- 每个意思保持**单一事实源**:唯一权威之地,改行为只改一处。**重复**
  (同一意思存在多处)花维护、花 token,还把一个意思在层级上的显著度
  吹到它真实地位之上。(引导词的意外反面:引导词故意重复 token,永不
  重复意思。)
- **环境**也是事实源(`package.json` 脚本、配置文件、目录布局、
  `--help` 输出),复述环境的文档是一个**缓存**:一份查询的副本,只在
  查询昂贵时才配花这份负载。缓存 agent 抬头看不到的东西:没写下来的约
  定、选择背后的原因、没有任何配置肯招供的坑。一文件一命令就能查到的,
  留给环境——在那儿它们不会过期。
- 逐行检查**相关性**:它还和文档的职能相关吗?一行失去相关性,要么是
  从来不相关(纯粹的展开叙述,或一个本该披露的分支),要么是随着它描
  述的行为或世界变化而过期。文档越短越容易保持相关。没有修剪纪律,默
  认的命运是**沉积**(sediment):陈旧的层因为"加着安全、删着危险"而
  沉下来,直到你必须钻透它们去找还活着的东西。
- 逐句猎杀**空转指令**(no-op):模型默认就会照做的指令,花了负载却什
  么都没说。检验(它相对默认行为改变了什么?)是相对模型的,不是相对
  读者的:两人争论一条是不是空转,争的其实是默认行为是什么,靠跑这份
  文档解决,不靠辩论。一句不合格,整句删掉,别只修剪字词。这个检验也
  给引导词打分:弱到压不过默认行为的词(_be thorough_,当 agent 本来就
  大致 thorough)是空转,解法是换更强的词(_relentless_),不是换技
  术。
